# 跨平台构建指南

> 目标：一条命令 / 一个菜单构建 Windows、macOS、Linux、Android、WebGL、iOS（Xcode 工程）。
> 构建入口：`Editor/Build/ReunionMovementBuilder.cs`。
> 裁剪保护：`Assets/ReunionMovement/link.xml`。

## 1. 菜单

`ReunionMovement → 构建 →`

| 菜单 | 目标 | 输出 |
|---|---|---|
| Windows (x64) | `StandaloneWindows64` | `Build/Windows/<Product>.exe` |
| macOS | `StandaloneOSX` | `Build/macOS/<Product>.app` |
| Linux (x64) | `StandaloneLinux64` | `Build/Linux/<Product>.x86_64` |
| Android (APK) | `Android` | `Build/Android/<Product>.apk` |
| WebGL | `WebGL` | `Build/WebGL/` |
| iOS (Xcode 工程) | `iOS` | `Build/iOS/`（仅 macOS） |

场景取 **Build Settings 里启用的项**；没有启用场景会直接失败并提示。

## 2. 命令行

```powershell
# 构建当前 Active Build Target
Unity -batchmode -quit -projectPath Unity/ReunionMovement `
  -executeMethod ReunionMovement.EditorTools.Build.ReunionMovementBuilder.BuildFromCommandLine

# 显式指定目标（不依赖 Active Target）
Unity -batchmode -quit -projectPath Unity/ReunionMovement `
  -executeMethod ReunionMovement.EditorTools.Build.ReunionMovementBuilder.BuildFromCommandLineWithTarget `
  -reunionTarget Android
```

`-reunionTarget` 接受 `windows` / `macos` / `linux` / `android` / `webgl` / `ios`。

> Unity 同一工程只允许一个实例。批量构建前关闭编辑器；`Tools/unity-verify.ps1` 也遵循同一约束。

## 3. 构建前检查

`Preflight()` 会输出：

| 检查 | 行为 |
|---|---|
| Build Settings 是否有启用场景 | 没有则失败 |
| `link.xml` 是否存在 | 缺失只告警；IL2CPP + 高裁剪时需补 |
| Android scripting backend | 非 IL2CPP 告警 |
| Android ARM64 | 未勾选告警（Google Play 要求） |
| WebGL 压缩 / decompressionFallback | 打印当前设置 |
| iOS + 非 macOS | 直接失败（iOS 构建只能在 macOS 上执行） |

## 4. `link.xml` 与自定义入口

`link.xml` 目前保留：

| 程序集 / 类型 | 为什么 |
|---|---|
| `ReunionMovement.Core.GameEntryResolver` | 用 `Attribute.GetCustomAttribute` + `Activator.CreateInstance` 找入口 |
| `ReunionMovement.Core.Base.ReunionGameEntryAttribute` | 入口声明特性 |
| `ReunionMovement.Core.StartGame` | 仓库示例入口 |
| `ReunionMovement.GenerateScript.AutoScripts`（整程序集） | Excel 配置数据 + Newtonsoft 泛型反序列化 |
| `ReunionMovement.GenerateScript.UI`（整程序集） | 生成的 UI 控制器，场景/预制体按 GUID 引用 |
| `ReunionMovement.GameConfig` | `Resources.Load<GameConfig>` + ScriptableObject 字段 |

**接入自己的游戏时**：如果你的入口类型只通过 `[assembly: ReunionGameEntry(typeof(X))]` 被反射实例化，
请在你自己的程序集里加一条：

```xml
<linker>
  <assembly fullname="MyGame">
    <type fullname="MyGame.MyGameEntry" preserve="all" />
  </assembly>
</linker>
```

或给入口类型加 `[UnityEngine.Scripting.Preserve]`。

## 5. 平台备注

### Android

- 推荐 IL2CPP + ARM64；`Player Settings → Other Settings` 里设置。
- 本机安装 Android Build Support 后，SDK / NDK / OpenJDK 位于
  `PlaybackEngines/AndroidPlayer/{SDK,NDK,OpenJDK}`，Gradle 位于 `Tools/gradle`。
- 首次构建会解析 Gradle 依赖；debug APK 使用默认 debug keystore。
- `VIBRATE` 权限由 `Editor/Build/AndroidVibratePermission.cs` 在 Gradle 主清单里自动注入，
  不需要手写 `AndroidManifest.xml`。已通过一次 release APK 构建确认注入生效
  （`unityLibrary/src/main/AndroidManifest.xml` 里包含 `android.permission.VIBRATE`）。
- `link.xml` 生效于 IL2CPP；本次 Android release 构建已完成 IL2CPP + Gradle 全链路，0 错误。

### iOS

- 只能在 macOS 上构建；本仓库的 Windows 环境无法做最终链接验证。
- 触觉实现位于 `Plugins/iOS/ReunionHaptics.mm`，与 `VibrationUtil` 的 9 个 `__Internal` 符号一一对应。
- 导出 Xcode 工程后，仍需在 Xcode 里配置签名 / Team。

### WebGL

- 线程不可用：网络层已自动回退到 WebSocket（见 `NetworkChannelFactory`）。
- 存档落盘使用 `persistentDataPath`（IDBFS），刷新页面后的持久化行为建议真机验证一次。
- 体积优化：`ImageEx` Shader 变体剥离 + Brotli 压缩 + `decompressionFallback`。

## 6. CI 矩阵

`.github/workflows/unity-ci.yml`：

| Job | 触发 | 内容 |
|---|---|---|
| `editmode-tests` | PR / main | EditMode 测试 + 架构守卫用例 |
| `guard-only` | PR / main | 不依赖 Unity 的快速守卫 |
| `webgl-build` | main / 手动 | WebGL 构建 |
| `windows-build` | main / 手动 | Windows x64 构建 |
| `android-build` | 手动 | Android debug APK |

Android 只在手动触发，避免每个 PR 烧约 2 小时；Windows / WebGL 在 main 上跑，PR 不跑构建。
需要仓库 Secret `UNITY_LICENSE`。

## 7. 验收

```powershell
# 1. 编译
dotnet build Unity/ReunionMovement/Assembly-CSharp-Editor.csproj

# 2. Unity 侧
pwsh Tools/unity-verify.ps1

# 3. 构建（Windows 示例）
Unity -batchmode -quit -projectPath Unity/ReunionMovement `
  -executeMethod ReunionMovement.EditorTools.Build.ReunionMovementBuilder.BuildFromCommandLine
```

构建产物在 `Unity/ReunionMovement/Build/`（被 `.gitignore` 忽略）。
