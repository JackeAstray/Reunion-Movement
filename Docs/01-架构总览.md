## 二、启动时序

### 阶段 1：静态复位（`SubsystemRegistration`）

`Bootstrap.ResetStaticStateOnPlay()` —— 关闭 Domain Reload 时静态字段不会自动清空，这里统一复位：

- 引擎静态状态（`GameEngine.ResetStaticState()`）；
- 入口解析缓存（`GameEntryResolver.Refresh()`）；
- 7 个 MonoBehaviour 管理器由 Modules 程序集的 `SingletonResets` 在同一个 `SubsystemRegistration` 阶段自行复位
  （清单在 `Framework/Modules/SingletonResets.cs`；Runtime 不引用 Modules）。

### 阶段 2：创建引擎（`BeforeSceneLoad`）

```
Bootstrap.OnBeforeSceneLoad()
 ├ ForceDisable? → 直接返回
 ├ Options.IsTestScene(当前场景名)? → IsTestScene = true（不返回，继续初始化）
 └ InitializeEngineAsync()
     ├ ErrorReporter.Initialize()                      全局错误捕获
     ├ entry = Options.Entry ?? GameEntryResolver.CreateEntry()
     │        （都没有 → 报错并跳过启动；AllowBuiltInEntryFallback=true 时才用内置 StartGame）
     ├ Bootstrap.StartAsync(entry)
     │   ├ EnsureDriver()                              [GameEngineDriver] + DontDestroyOnLoad
     │   ├ GameEngine.Create()                         复位静态状态 / 重建静态 Subject
     │   ├ driver.Bind(engine)
     │   ├ modules = ((GameEntry)entry).CreateModules() 14 个模块，顺序即初始化顺序
     │   └ engine.LaunchAsync(entry, modules, timeout: Options.LaunchTimeoutSeconds)
     └ 失败 → CleanupFailedStartup()
```

**入口是可替换的**：在你自己的程序集里写一行即可，不需要改框架源码。
示例工程的入口声明在 `Game/StartGameEntry.cs`（`Assembly-CSharp`，不会打进 UPM 包）。

```csharp
[assembly: GearGameEntry(typeof(MyGame.MyGameEntry))]
```

解析规则：`Bootstrap.Options.Entry` 优先，其次 `Framework/Runtime/GameEntryResolver.cs` 的程序集声明；
两者都没有时报错并跳过启动（不再隐式回退 `StartGame`，避免接管宿主工程）。
确实需要内置入口时，显式设置 `Bootstrap.Options.AllowBuiltInEntryFallback = true`。

**手动掌控启动**（跳过自动启动）：

```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void ManualBoot()
{
    Bootstrap.Disable();
    Bootstrap.Options.TestSceneContains = new[] { "Sandbox" };   // 可选
    Bootstrap.StartAsync(new MyGameEntry()).Forget();
}
```

> 手动启动若发生在 `SubsystemRegistration` 之前，Modules 的模块来源与错误捕获尚未注册：
> 需要 Timer / Network / Http 时先调用 `ModuleSourceRegistration.EnsureRegistered()`，
> 需要错误捕获时先调用 `ErrorReporter.Initialize()`；或把启动延后到 `SubsystemRegistration` 之后。

### 阶段 3：`LaunchAsync` 的三个阶段

| 状态 | 动作 | 说明 |
|---|---|---|
| `BeforeInit` | `entry.OnBeforeInitAsync()` | `Config.EnsureLoaded()`、`GameOption.LoadOptions()` |
| `Initializing` | 逐个 `module.Init()` | 串行；每完成一个广播聚合进度到 `OnInitProgressSubject` |
| `Starting` | `entry.OnGameStartAsync()` | 语言设置 → 测试场景则跳过 → `LoadScene("Temp")` → 打开 `StartGameUIPlane` |
| `Running` | — | `ModuleRuntime.IsEngineRunning = true`，开始每帧驱动 |

失败/超时/取消都会走 `FailInit`：标记 `Failed` → `ClearModuleData()` → 广播 `OnInitFailedSubject`。

超时用 `PlatformTimeout`（PlayerLoop 驱动）而不是 `CancellationTokenSource(TimeSpan)` —— 后者在 WebGL 上永不触发。

### 阶段 4：每帧驱动（`GameEngineDriver` → `GameEngine`）

`GameEngineDriver` 是唯一的 MonoBehaviour 桥接，把 `Update` / `LateUpdate` / `FixedUpdate` / `OnApplicationPause|Focus|Quit` / `OnDestroy` 转发给纯 C# 的 `GameEngine`。

`OnUpdate` 做三件事：

1. 广播 `UpdateSubject`；
2. 累计真实时间，触发 `UpdatePer300msSubject` / `UpdatePer1sSubject`（用 `unscaledDeltaTime`，暂停时仍走）；
3. 快照遍历 `ISystemUpdatable` 模块，逐个 `try/catch` 隔离异常。

## 三、模块契约

```csharp
public interface ICustomSystem : ISystemInitializable   // 必须实现
public interface ISystemUpdatable        { void Update(float logicTime, float realTime); }
public interface ISystemFixedUpdatable   { void FixedUpdate(float fixedDeltaTime); }
public interface ISystemLateUpdatable    { void LateUpdate(float logicTime, float realTime); }
public interface ISystemDisposable       { void Clear(); }
```

- `logicTime` 受 `timeScale` 影响，`realTime` 不受影响。暂停时 `logicTime` 归零，需要"暂停也继续跑"的逻辑用 `realTime`。
- 引擎在 `Init` 阶段按接口类型预过滤出三个更新列表；之后每帧只遍历对应列表。
- 更新循环用快照遍历，模块在自己的 `Update` 里增删其他模块不会导致同帧重复驱动。
- 模块被意外销毁（Unity fake-null）会被自动移出更新列表。

### 声明初始化顺序：`[ModuleOrder]`

模块类上标注排序值与依赖，启动时由 `ModuleCatalog` 做稳定拓扑排序并校验：

```csharp
[ModuleOrder(20, typeof(ResourcesSystem))]   // 排序值 20，且要求 ResourcesSystem 先初始化
public class AddressableSystem : ICustomSystem { ... }
```

- 不标注 = `Order 0` + 保持注册顺序，因此**既有模块可以逐个补**，不会一次性全红。
- 校验项：缺依赖、重复注册、`null` 项、依赖成环。**校验失败不中断启动**，沿用注册顺序并写日志。
- 启动日志里会有一行 `模块顺序: ResourcesSystem(10) → … → HttpMgr(140)`，排查"初始化时序"问题先看它。

## 四、拿到一个系统的几种方式

| 方式 | 示例 | 适用 |
|---|---|---|
| 静态单例（Runtime 系统） | `UISystem.Instance` | 11 个 Framework.Runtime 系统 |
| 纯 C# 单例（Modules） | `TimerMgr.Instance` / `HttpMgr.Instance` / `NetworkMgr.Instance` | Framework.Modules 的 Timer / Http / Network（引擎驱动） |
| 引擎模块列表 | `Modules.Get<UISystem>()` | 需要"只拿真正注册过的模块"时 |

`Modules` 与 `.Instance` 的关键区别：`.Instance` 是各程序集自建的单例（`Lazy<T>` 或 MonoBehaviour 懒创建），模块**没注册**也能拿到一个
"没人 `Init()`、没人 `Update()`"的假对象；`Modules.Get<T>()` 只认引擎持有的实例，取不到时抛出的异常里
会列出当前已注册的全部模块。

**约定（当前）**：既有代码继续用 `Xxx.Instance`；新代码优先 `Modules.Get<T>()`；不要自己去 `new` 系统；
不要在 `Init()` 之前调用系统方法。`.Instance` 的弃用要等调用点批量迁移后再做（见 [重构方案](design/重构方案.md) 阶段 2 状态说明）。


## 五、全局事件

`GameEngine` 上有一组 R3 Subject，静态可订阅：

| Subject | 时机 |
|---|---|
| `OnInitializedSubject` | 初始化全部完成 |
| `OnInitFailedSubject` | 初始化失败（携带错误信息） |
| `OnInitProgressSubject` | 聚合初始化进度 0~100 |
| `OnStateChangedSubject` | 生命周期状态变化 |
| `UpdateSubject` / `UpdatePer300msSubject` / `UpdatePer1sSubject` | 每帧 / 300ms / 1s |
| `OnAppPauseSubject` / `OnAppFocusSubject` | 应用前后台 / 焦点 |

订阅务必用 `AddTo(this)` 之类的销毁绑定，否则对象销毁后回调仍会打到已释放对象。

## 六、状态机

```
Uninitialized → BeforeInit → Initializing → Starting → Running ⇄ Paused
                     ↓            ↓            ↓
                   Failed ←───────┴────────────┘
Running/Failed → Disposed
```

`Dispose()` 会取消在途初始化、`ClearModuleData()` 逐个调 `Clear()`、置空静态 Subject、把 `Current` 置 null。引擎可以重建（`GameEngine.Create()` 检测到 `Failed`/`Disposed` 会允许新建）。

## 七、还没搞定的地方

按影响排序，详见 [重构方案](design/重构方案.md)：

1. 两套获取方式并存：`Xxx.Instance`（守卫基线 117 处，只减不增）与 `Modules.Get<T>()`；运行时新代码应走后者。
2. ~~两套 Update 驱动~~ —— 已消除：`TimerMgr` / `HttpMgr` / `NetworkMgr` 全部为纯 C# 单例，
   只由引擎 `ISystemUpdatable` 驱动。两个旧示例场景的 `NetworkMgr` 组件已改为空的
   `NetworkMgrSceneAdapter` 兼容壳，可随时删除；`ModuleRuntime` 已删除。
3. ~~`Framework/Runtime` 直接引用 `Framework/Modules`~~ —— 已解耦：`Modules` 通过 `Base` 的
   `ModuleSourceRegistry`（Timer / Network / Http）与 `ResolutionBridge`（ResolutionMgr）注册能力，
   `Framework/Runtime.asmdef` 不再引用 `Modules`，守卫会拦截回退。
   `TimerMgr` / `HttpMgr` / `NetworkMgr` 均已改为纯 C# 单例；两个旧示例场景用空的
   `NetworkMgrSceneAdapter` 过渡，避免 Missing Script。
4. 巨型类：仍有 17 个文件 > 600 行、1 个 > 1000（`LoopScrollRect` 1336 行，已约定不拆）。
