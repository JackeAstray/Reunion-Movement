# ReunionMovement 工具箱

ReunionMovement 工具箱把首次使用、项目检查、资源处理、数据工具和发布入口集中在一个窗口中。

打开方式：Unity 菜单 `ReunionMovement → 工具箱`。

## 1. 项目概览与检查

窗口打开后会检查以下内容：

- 当前 Unity 版本是否符合项目建议的 Unity 6000.3+；
- Addressables 与 Input System 是否已经安装；
- ReunionMovement 资产根目录、`GameConfig` 和源码生成器是否存在；
- 注册的 Addressables Settings（支持自定义位置），以及预期的 9 个分组、7 个 Label、DevLocal / Publish Profile 名称；
- 主要使用文档是否存在；没有仓库完整文档时回退到随包简明指南。

检查本身只读取项目状态，不会自动安装 Package、创建配置、迁移资源或执行构建。检查项右侧的按钮用于定位资产、打开文档，或者在用户主动点击后调用对应的现有菜单。

## 2. 两条开始路径

### 路径 A：最快运行

适合第一次导入插件或只使用 Resources 的项目：

1. 打开工具箱并确认必需检查项没有错误；
2. 点击“定位 GameConfig”；缺失时点击“创建 GameConfig…”并确认，默认配置的热更新关闭，已有资产不会被覆盖；
3. 保持 `enableHotUpdate` 关闭；
4. 从下拉列表选择插件内示例，点击“打开所选场景”，保存当前场景后再进入 Play Mode。运行中不能切换场景。

此路径不要求先迁移 Addressables 资源，也不会访问远程 CDN。

### 路径 B：Addressables / 远程热更

需要远程资源或内容更新时使用：

1. 点击“初始化配置”；
2. 点击“迁移全部资源”；
3. 点击“构建当前平台”；
4. 按《远程部署指南》配置 CDN，再使用上传或一键流水线。

迁移、构建和上传都可能修改项目资产或生成构建产物，因此工具箱不会自动执行这些步骤。

工具箱的一键流水线固定面向 **WebGL**（不是当前平台），会补齐配置、迁移资源、按需切换平台及启用远程 Catalog；OSS 凭据齐全时还会上传到外部服务。执行前会明确确认这些影响。只需要本地内容时，请使用分步构建入口。

工具箱菜单操作在编译、资产导入、Player 构建或 Play Mode 下会被拒绝。延迟执行前会再次检查，不会在编辑器空闲后自动重试。此保护仅覆盖工具箱入口，不更改原菜单和 CI 批处理的行为。

## 3. 常用工具

工具箱底部的按钮只是调用现有功能，实际逻辑仍保留在对应工具中：

- Addressables Groups、迁移、构建和一键流水线；
- `.unitypackage` 导出；
- Excel 转脚本、Excel 转 JSON；
- 场景切换、屏幕日志、FPS 等小功能；
- 快速开始、打包、远程部署和 UI 输入文档。

如果按钮提示菜单无法执行，先查看 Console 是否存在编译错误，并检查对应依赖是否已经安装。

## 4. 模块扩展

“扩展模块”区支持复制 [CustomSystem 模板](../Unity/ReunionMovement/Assets/ReunionMovement/Documentation/CustomSystem.cs.txt)，并定位注册入口和 Core 目录。不自动修改启动列表。

模板必须保存到 Core/System 下以沿用 Core 程序集；按 [随包使用指南](../Unity/ReunionMovement/Assets/ReunionMovement/Documentation/ReunionMovement%20使用指南.md) 的步骤在 CreateModules() 显式注册。初始化进度为 0–100，Update 和 Clear 接口按需保留。

## 5. 验证范围与 Unity 内验收

已完成代码审查，以及引用 Unity 6000.3.10f1 真实程序集、UniTask DLL 和真实接口源码的独立编译；窗口和模板均通过（0 警告、0 错误）。此外，Unity 实际生成的 ReunionMovement.Toolbox.Editor.csproj 通过 dotnet build --no-restore 构建，同样为 0 警告、0 错误，验证了工具箱 asmdef 的真实引用和编译路径。这仍不等于完整 Unity 项目编译或窗口交互验收。此前 Unity batch 启动提前退出，未取得有效编译结果。

以下交互尚需在 Unity 内验收，建议使用项目副本：

1. 等待编译完成，打开工具箱，确认没有 IMGUI/Console 异常；仅打开窗口不应创建或修改资产。
2. 对照 Inspector 核对 GameConfig 运行模式；在副本移走配置后测试创建确认、取消和已有路径保护。
3. 修改当前场景但不保存，打开所选示例，测试保存提示的取消分支；在 Play Mode 验证禁止切换。
4. 对照 Addressables Groups 核对配置诊断；配置完整时能定位，缺少预期项时能显式补齐。不要仅凭名称齐全就发布远程内容。
5. 在副本中复制模板到推荐目录，按说明注册；确认导入编译通过后再运行。不要在生产项目随意替换启动列表。
6. 迁移、构建和流水线先测试取消确认。实际构建须另行核对平台和 Profile；OSS 上传只在明确确认远程目标后测试。
