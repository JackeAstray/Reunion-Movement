# 远程部署指南（CDN + 全平台）

> 目标：把 Remote 分组的 Bundle 部署到 CDN，实现客户端远程热更；覆盖全平台打包。

## 0. 远程 Catalog 说明

**Catalog（目录）** 是 Addressables 的资源清单（记录 地址 → Bundle → hash）。客户端启动时先加载它，才知道"资源在哪、去哪个 Bundle 找"。

**远程 Catalog** = 把这份清单放到 CDN，作用是为**版本对比 / 热更检测**提供远端基准：
```
客户端启动
  └─ 加载本地 catalog（内置）
  └─ 对比远程 catalog hash（拉 CDN 的 catalog_*.json）
      ├─ 相同 → 无更新，用本地
      └─ 不同 → 下载新 catalog + 变更的 Remote bundle
```
没有它：`CheckForCatalogUpdates()` 永远查不到更新（无远端清单可比对），热更失效。

**开启是否妨碍本地加载？不会。** 开启只是构建产物**多一份远程 catalog**（Addressables 2.9.x 为二进制 `catalog_*.bin` + 同名 `.hash`；旧版 JSON 为 `catalog_*.json`）供上传 CDN：
- BuiltIn 本地资源仍走本地 catalog + StreamingAssets，0 网络依赖；
- `AddressableSystem` 仅在 `addressablesMode = Remote` 时检查更新，失败只告警不阻断启动；
- `LocalOnly` 模式完全不联网。

**注意**：开启远程 Catalog 本身不产生 Remote Bundle——热更目标必须已把资源标记进 `Remote_*` 分组（用「迁移 → 音频/图片」菜单），否则没有可热更的远端资源。

## 1. 整体流程

```
[启用远程 Catalog] → 配置 Profile → 构建 Content → 上传 Remote Bundle 到 CDN → 配置 GameConfig → 发版
```

> **远程 Catalog 默认关闭**。热更依赖构建期生成远程 catalog（`catalog_*.json`），
> 构建前必须执行一次 `ReunionMovement → Addressables → 启用远程 Catalog（Phase 3 热更）`
> （默认 `m_BuildRemoteCatalog=false`，未开启时不会生成远程 catalog，`CheckForCatalogUpdates` 永远无更新）。
> 也可在「构建 Content」时弹出的提醒里选「启用并构建」。

## 2. 全平台打包说明

- Addressables 构建路径含 `[BuildTarget]` 占位符，产物自动分目录：`Library/com.unity.addressables/aa/<平台>/`
- **各平台产物互不覆盖、可并存**，同一份 `version.json` 记录 `platform` 字段区分
- 内置 Bundle 随对应平台 Player 打包进 `StreamingAssets`，无需单独上传
- 运行时 `Remote.LoadPath` 中的 `[BuildTarget]` 自动替换为客户端实际平台，**每个客户端只拉自己平台的 bundle**

### 构建入口
| 菜单 | 用途 |
| --- | --- |
| `构建 Content（当前平台）` | 按 Unity 当前激活平台构建 |
| `构建 → 选择平台并构建…` | 列出 Windows/macOS/Linux/Android/iOS/WebGL，选平台自动切换并构建 |

### version.json（构建自动生成）
```json
{
  "version": "0.1.0",
  "platform": "WebGL",
  "buildTime": "...",
  "catalogHash": "...",
  "catalogFile": "...",
  "remoteCatalogFolder": ".../ServerData/WebGL",
  "remoteUploadFolder": "Library/com.unity.addressables/aa/WebGL",
  "bundleCount": 8,
  "bundles": [ { "name": "...bundle", "md5": "...", "size": 123 } ]
}
```
`remoteUploadFolder` 即该平台 **Bundle 所在目录**；`remoteCatalogFolder` 即该平台 **远程 catalog（`catalog_*.bin`/`.hash`）所在目录**（`Remote.BuildPath` 求值，如 `ServerData/WebGL`）；`bundles` 的 md5 用于上传后核对。

## 3. 部署到 CDN

### 3.1 自动上传（推荐：阿里云 OSS）
项目内置 `AddressablesCdnUploader`（纯 C# 实现 OSS HTTP PUT + 签名，无需第三方 SDK），
构建后一键增量上传 **Bundle + 远程 catalog** 到 OSS（自动收集 `remoteUploadFolder` 下的 `.bundle` 与 `remoteCatalogFolder` 下的 `catalog_*.bin`/`.hash`）：

| 菜单 | 用途 |
| --- | --- |
| `ReunionMovement → Addressables → OSS 上传配置…` | 填写 Endpoint / Bucket / AK / SK / Prefix（存本机 EditorPrefs，不入库） |
| `ReunionMovement → Addressables → 上传到 OSS（增量）` | 读 version.json → 增量对比 md5 → 上传变化文件 |

**使用步骤**
1. 阿里云控制台创建 OSS Bucket（建议私有，工具上传时自动设对象 `public-read`）。
2. 创建**最小权限 RAM 子账号**：仅 `oss:PutObject` 权限，拿 AK/SK。
3. 配置：`OSS 上传配置…` 填 `Endpoint`（如 `https://oss-cn-hangzhou.aliyuncs.com`）、`Bucket`、`AK`、`SK`、`Prefix`（默认 `reunion/{version}`）。
4. 先「启用远程 Catalog」→「构建 Content」，再「上传到 OSS（增量）」→ 完成后确认日志。

**增量机制**：上传状态存 `Build/Addressables/upload_state.json`（key→md5），
重复上传只传输 md5 变化的文件；删除该文件即强制全量。

**上传目录结构**（与 CDN 目录建议一致）：
```
{prefix}/{platform}/          # 如 reunion/v0.1.0/WebGL/
├── xxx.bundle
└── catalog_*.bin + catalog_*.hash
```

> 安全提醒：AK/SK 仅存本机，勿提交版本库；建议使用最小权限 RAM 子账号并定期轮换。

### 3.2 手动上传（无 OSS 时）

### 步骤
| 步骤 | 操作 |
| --- | --- |
| ① 启用远程 Catalog | 菜单 `ReunionMovement → Addressables → 启用远程 Catalog（Phase 3 热更）`（默认关闭，需手动开启） |
| ② 配 Profile | Groups 窗口把 `Publish` Profile 的 `Remote.LoadPath` 改为真实 CDN，如 `https://cdn.example.com/reunion/{version}/`（`{version}` 会被替换），并切换激活 Profile 到 `Publish` |
| ③ 构建 | 用 §2 的菜单按目标平台构建 |
| ④ 上传 | 把 `remoteUploadFolder` 目录内的 `.bundle` 与 `remoteCatalogFolder`（如 `ServerData/WebGL`）内的 `catalog_*.bin`/`.hash` 上传到 CDN 对应平台子目录（也可用「上传到 OSS（增量）」自动完成） |
| ⑤ 配置运行时 | `GameConfig`：`addressablesMode = Remote`，`remoteBundleUrl`/`remoteCatalogUrl` 填 CDN 地址 |
| ⑥ 发版 | 打对应平台 Player（内置 Bundle 自动进 StreamingAssets） |

### CDN 目录建议
```
reunion/
└── v0.1.0/              # {version}
    ├── Windows/
    ├── Android/
    ├── iOS/
    └── WebGL/           # 该平台的 .bundle + catalog_*.bin/.hash
```

## 4. WebGL 服务器配置

### 4.1 阿里云 OSS（自动上传场景）
OSS Bucket 控制台开启 **CORS 规则**（WebGL 跨域拉取必需）：
```xml
<?xml version="1.0" encoding="UTF-8"?>
<CORSConfiguration>
  <CORSRule>
    <AllowedOrigin>*</AllowedOrigin>
    <AllowedMethod>GET</AllowedMethod>
    <AllowedMethod>HEAD</AllowedMethod>
    <AllowedHeader>*</AllowedHeader>
    <MaxAgeSeconds>3000</MaxAgeSeconds>
  </CORSRule>
</CORSConfiguration>
```
同时建议：对象 `Content-Type` 保持 `application/octet-stream`（工具已处理）；
bundle 文件名带 hash 可强缓存，catalog 文件设 `no-cache`（OSS 控制台/API 配置元数据或 CDN 缓存规则）。

### 4.2 同域部署（推荐）
把 bundle 与 `index.html` 放同一域名，避免 CORS。

### 4.3 跨域部署（Nginx 示例）
```nginx
location /reunion/ {
    # CORS（跨域必需）
    add_header Access-Control-Allow-Origin *;
    add_header Access-Control-Allow-Headers "X-Unity-Version, Content-Type";

    # bundle 文件类型（Unity 依赖正确 MIME）
    default_type application/octet-stream;

    # bundle 文件名带 hash，可强缓存；catalog 建议 no-cache
    location ~* \.bundle$ {
        expires 30d;
    }
    location ~* catalog_.*\.(bin|hash|json)$ {
        expires -1;
    }
}
```

> 其他服务器（OSS/S3/CDN 厂商）同样需要：正确 Content-Type、允许跨域头、bundle 强缓存 + catalog 不缓存。

## 5. 版本更新流程（热更闭环）

1. 修改任意 Remote 分组资源（如 `Remote_Sounds` 里的音频）
2. 重新构建 Content（version.json 的 catalogHash 会变化）
3. 把新产物上传到 **新的 version 目录**（或覆盖，取决于策略）
4. 客户端启动时 `AddressableSystem.Init()` 自动执行 `CheckUpdateAsync`：
   - 对比本地与远程 catalog hash
   - 有更新 → `UpdateContentAsync` 下载新 catalog + Bundle（带进度）
   - 下载后 Addressables 自动切换新 catalog，后续加载命中新资源

### 运行时相关 API
| API | 说明 |
| --- | --- |
| `AddressableSystem.CheckUpdateAsync()` | 检查是否有可更新 catalog |
| `AddressableSystem.UpdateContentAsync(result, progress)` | 下载并应用更新 |
| `AddressableSystem.CleanBundleCache()` | 清理无用 Bundle 缓存（WebGL 为 IndexedDB） |
| `AddressableSystem.GetDebugStats()` | 查看活跃句柄/待更新 catalog 数 |

> 完整更新流程示例（如需要可接入启动/设置页）：
> ```csharp
> var result = await AddressableSystem.Instance.CheckUpdateAsync();
> if (result.hasUpdate)
>     await AddressableSystem.Instance.UpdateContentAsync(result, progress);
> ```

## 6. 常见问题

| 问题 | 处理 |
| --- | --- |
| 客户端拉不到远程资源 | 检查 `remoteBundleUrl` 是否以 `/` 结尾、CDN 是否包含对应平台子目录、CORS 头 |
| WebGL 跨域报错 | 确认服务器返回 `Access-Control-Allow-Origin`，且 bundle 的 Content-Type 正确 |
| 更新后资源还是旧的 | catalog 被缓存；服务器上远程 catalog（`catalog_*.bin`/`.hash`）应 no-cache；或 `CleanBundleCache` |
| 平台切换后构建路径变化 | 属正常（`[BuildTarget]` 分目录）；上传时按 `remoteUploadFolder` 提示的目录 |
