# 快速开始

> 目标：让 ReunionMovement 的 Addressables 集成在 5 分钟内跑起来（本地模式，无需 CDN）。

## 1. 前置依赖

| 依赖 | 版本 | 说明 |
| --- | --- | --- |
| Unity | 6000.3+ | 与项目一致 |
| `com.unity.addressables` | 2.9.1 | 已在 `Packages/manifest.json`；若在接收方项目需手动安装 |

## 2. 配置（全自动，无需手动）

打开 Unity 后，`AddressablesSetup` 的 `[InitializeOnLoad]` 会自动创建：

- `Assets/AddressableAssetsData/`（Addressables 默认配置）
- **9 个分组**：`BuiltIn_Config/UI/Prefabs/Fonts/Shaders`、`Remote_Sounds/Textures/Scenes/AutoDatabase`（Remote 分组自动校验/修正为 Remote 路径变量）
- **7 个 Label**：`builtin` / `remote` / `ui` / `sound` / `texture` / `scene` / `data`
- **2 个 Profile**：`DevLocal`（本地模拟，**默认激活**）/ `Publish`（CDN）
- **远程 Catalog 默认关闭**（`m_BuildRemoteCatalog=false`）：Phase 3 部署 CDN 前无需开启；需要热更时执行 `ReunionMovement → Addressables → 配置/启用远程 Catalog（Phase 3 热更）`

> **远程 Catalog 是什么？** Catalog（目录）是 Addressables 的资源清单（记录地址→Bundle→hash）。
> 远程 Catalog = 把这份清单放到 CDN，用于**版本对比 / 热更检测**：客户端启动时拉取远端
> `catalog_*.json`，与本地 hash 比对，不同则下载新 Remote Bundle。**它不是资源本身**。

> **开启会不会妨碍本地加载？不会。** 开启只是让构建产物**多生成一个 `catalog_*.json`**（供上传 CDN），
> 对本地加载无任何影响：
> - BuiltIn 本地资源仍走本地 catalog + StreamingAssets，0 网络依赖；
> - `AddressableSystem` 仅在 `addressablesMode = Remote` 时才执行更新检查，且失败只告警、不阻断启动；
> - `LocalOnly` 模式完全不联网。
> 唯一"代价"是上传 CDN 时多传一个 catalog 文件。

> 手动补齐入口：`ReunionMovement → Addressables → 配置/初始化配置`（幂等，重复执行无副作用；会顺带修复已存在分组的错误远程路径）。

## 3. 第一次跑通（本地，3 步）

1. **（可选）迁移资源**：`ReunionMovement → Addressables → 迁移 → 一键迁移全部（UI+音频+图片）`
   - 将 `Resources/Prefabs/UIs/`（及其 Resources 内依赖）、`Resources/Sounds`、`Resources/UI/Sprites` 复制到 `Assets/AddressableAssets/` 对应分组并标记 Addressable（幂等，可重复执行；也可按需单项补迁）
   - 不迁移也能运行（异步加载自动降级 Resources），但要走 Addressables 必须执行
2. **运行游戏**：默认 `addressablesMode = LocalOnly`，直接 Play
3. **看日志**：启动界面打开时出现 `[UISystem] LoadWindowAsync(...) 从 Addressables 加载成功` 即成功

## 4. 常用代码示例

```csharp
// 异步打开 UI（推荐，Addressables 优先，失败降级 Resources）
await UISystem.Instance.OpenWindowAsync<PopupUIPlane>(args);

// 直接加载资源
var sprite = await AddressableSystem.Instance.LoadAssetAsync<Sprite>(
    AddressableKeys.UIRoot + "SomeImage");
// ... 使用完释放
AddressableSystem.Instance.ReleaseAsset(sprite);

// 实例化 + 释放
var go = await AddressableSystem.Instance.InstantiateAsync(AddressableKeys.PrefabEnemy, parent);
AddressableSystem.Instance.ReleaseInstance(go);

// 双轨加载（Addressable 优先 → Resources 兜底）
var prefab = await AddressableSystem.Instance.LoadWithFallbackAsync<GameObject>(
    AddressableKeys.UIRoot + "StartGameUIPlane", Config.UIPath + "StartGameUIPlane");

// 调试统计（排查泄漏）
Debug.Log(AddressableSystem.Instance.GetDebugStats());
```

## 5. 配置项说明（`GameConfig`）

| 字段 | 默认值 | 说明 |
| --- | --- | --- |
| `enableAddressables` | true | 总开关；false 时 `AddressableSystem` 处于 `Off` 模式 |
| `addressablesMode` | `LocalOnly` | `Off`（纯 Resources）/ `LocalOnly`（仅本地）/ `Remote`（支持 CDN） |
| `remoteBundleUrl` | "" | 远程 Bundle 根地址（Remote 模式必填） |
| `remoteCatalogUrl` | "" | 远程 Catalog 地址（Remote 模式必填） |

> `AddressablesMode` 为 `Off` 时 `Config.AddressablesMode` 恒返回 `Off`（与 `enableAddressables` 联动）。

## 6. 常见问题

| 问题 | 处理 |
| --- | --- |
| 日志显示"降级 Resources 加载成功" | 未执行迁移菜单，或该资源未标记 Addressable |
| 找不到 `AddressableAssetsData` | 编辑器打开时自动生成；或手动「初始化配置」 |
| `OpenWindowAsync` 返回 null | 检查地址 `BuiltIn/UI/{名字}` 与分组内 entry 的 address 是否一致 |
