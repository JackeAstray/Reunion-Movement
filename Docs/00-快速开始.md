# 00 · 快速开始

> 目标：10 分钟内让工程跑起来，并完成第一次改动。

## 1. 环境

| 项 | 要求 |
|---|---|
| Unity | 6000.3.10f1（Unity 6.3，URP 17.3） |
| 模块 | TextMesh Pro、Addressables、Input System（`Active Input Handling` 需包含 Input System） |
| 平台 | Windows 优先；WebGL 有专门适配，移动端部分能力被跳过 |

首次打开会做一次全量导入（Library 约 2.3 GB），慢是正常的。

## 2. 跑起来

1. 打开工程根目录 `Unity/Gear`。
2. 等 Console 不再出现红色编译错误。
3. 打开场景 `Assets/Gear/Scenes/StartGame.unity`。
4. 按 Play。

按下 Play 之后的顺序（详见 [01-架构总览](01-架构总览.md)）：

```
Bootstrap（自动，无需场景物件）
  → 创建 [GameEngineDriver] 常驻物体
  → GameEngine.Create()
  → new StartGame() → CreateModules() 注册 14 个系统
  → LaunchAsync：OnBeforeInitAsync → 14 个模块 Init → OnGameStartAsync
  → 加载 "Temp" 场景 → 打开 StartGameUIPlane 启动界面
```

**没有"启动场景物件"**——引擎由 `[RuntimeInitializeOnLoadMethod]` 自动拉起，这是第一阶段重构要改善的点（见 [重构方案](design/重构方案.md) 阶段 1）。

## 3. 只看一个功能

打开 `Assets/Gear/Scenes/Example/` 下任意场景直接 Play。场景名以 `Test` / `_` 开头，或包含 `Example` / `UIPlaneScene` / `Music` / `Audio` / `Debug` 时，`Bootstrap` 会标记为测试场景、跳过自动跳转，保留当前场景。

也可以到处放 `Bootstrap.ForceDisable = true;` 彻底关掉自动启动，自己手动驱动引擎。

## 4. 第一次改动

### 改启动后打开哪个窗口

`Framework/Runtime/StartGame.cs` → `OnGameStartAsync()`：

```csharp
await SceneSystem.Instance.LoadScene("Temp", true, null, null);
await UISystem.Instance.OpenWindowAsync(StartGame.StartupWindowName);
```

窗口 Id 由控制器上的 `[UIWindow("...")]` 声明（示例见 `GenerateScript/UI/UIPlane/StartGameUIPlane.cs`），
`StartGame.StartupWindowName` 就是它的 Id。`UINames` 常量表已删除。

### 换成自己的游戏入口

框架自带的入口是 `Framework/Runtime/StartGame.cs`。要换成你自己的，**不需要改框架源码**：

```csharp
// 放在你自己程序集的任意 .cs 文件里（namespace 之外）
[assembly: GearGameEntry(typeof(MyGame.MyGameEntry))]

public class MyGameEntry : GameEntry
{
    public override IList<ICustomSystem> CreateModules() => new List<ICustomSystem>
    {
        ResourcesSystem.Instance,
        SceneSystem.Instance,
        UISystem.Instance,
    };

    public override UniTask OnBeforeInitAsync() => UniTask.CompletedTask;

    public override async UniTask OnGameStartAsync()
    {
        await SceneSystem.Instance.LoadScene("MainMenu", true, null, null);
    }
}
```

入口解析优先采用非框架程序集的声明；示例入口在 `Game/StartGameEntry.cs`（`Assembly-CSharp`，不进包），你自己的声明会优先生效。

### 加一个自己的系统

1. 复制 `Assets/Gear/Documentation/CustomSystem.cs.txt` 到 `Framework/Runtime/System/YourSystem/YourSystem.cs`。
2. 实现 `ICustomSystem`（必须 `Init()` 与 `InitProgress`；按需加 `ISystemUpdatable` / `ISystemDisposable`）。
3. 在类上加一行排序与依赖声明：
   ```csharp
   [ModuleOrder(150, typeof(UISystem))]   // 排在 UISystem 之后初始化
   public class YourSystem : ICustomSystem { ... }
   ```
4. 在 `Framework/Runtime/StartGame.cs` 的 `CreateModules()` 里 `modules.Add(YourSystem.Instance);`。

> 顺序不再由 `modules.Add` 的先后决定。启动日志里的 `模块顺序: …` 一行就是真实执行顺序；
> 写错依赖（依赖了没注册的模块、或依赖成环）会在同一行日志里给出具体原因，未标注的模块保持注册顺序。

> 工具箱（菜单 `Gear → 工具箱`）提供"复制模块模板"和"定位注册入口"。

### 加一个窗口

菜单 `Gear → 内容 → 生成 UI 窗口` 生成面板脚本骨架（已有同名文件不会覆盖），然后：
1. 给控制器加 `[UIWindow("你的窗口名")]`；
2. 用 `UISystem.Instance.OpenWindowAsync<你的控制器>()`，或按名称 `OpenWindowAsync("你的窗口名")` 打开。

### 编辑器工具

| 菜单 | 作用 |
|---|---|
| `Gear → 工具箱` | 环境检查、示例打开、模块模板 |
| `Gear → 开发 → 守卫 → 运行架构检查` | 跑全部架构守卫（行数 / `.meta` / 依赖方向 / 旧命名残留…） |
| `Gear → 内容 → 表格 -> 脚本` | Excel 导表 |
| `Gear → 打包 → 导出 .unitypackage` | 出包（旧方式，整目录） |
| `Gear → 打包 → 导出 UPM 包（运行时 / 完整 / OpenUPM 依赖）` | 生成可被 Package Manager 安装的 UPM 包（见 [UPM 打包指南](Packaging/UPM打包指南.md)） |
| `Gear → 构建 → Windows / macOS / Linux / Android / WebGL / iOS` | 多平台出包（见 [跨平台构建指南](guides/跨平台构建指南.md)） |
| `Gear → 开发 → 检查第三方依赖冲突` | 检测官方 UPM 包与内置副本重名（见 [第三方依赖](guides/第三方依赖.md)） |
| `Gear → Addressables → ...` | **默认关闭**；先在工具箱 `Addressables` 页或菜单「启用 Addressables」按需开启，之后才有迁移 / 构建 / 上传 OSS |

> 菜单顺序按段位固定：工具箱 → 打包 → 构建 → 内容 → Addressables → 开发（每段内部再按用途排序）。

架构守卫只在你**改坏了约定**时才报错：

| 报错 | 意思 | 怎么处理 |
|---|---|---|
| 超过 600 行且未登记基线 | 新写的类太长了 | 按职责拆成 `partial` 或独立类 |
| 已登记的文件又变大了 | 基线只允许变小 | 拆分，然后把新行数写回 `file-size-baseline.txt` |
| 缺少 `.meta` | 移动/新建文件没带 `.meta`，引用会静默丢失 | 把 `.meta` 一起提交 |
| asmdef 依赖方向违规 | 下层引用了上层 | 改成单向依赖，或用事件解耦 |
| `.Instance` 使用点超过基线 | 又走回了单例直取 | 运行时改用 `Modules.Get<T>()`；编辑器/测试里才用 `Instance` |
| `ICustomSystem` 缺 `[ModuleOrder]` | 初始化顺序退化成书写顺序，加一行就可能改变启动链 | 补 `[ModuleOrder(序号, typeof(依赖))]` |
| 旧命名残留 | 代码/模板/文档里还写着改名前的程序集名或目录路径 | 换成当前的 `Gear.Framework.Runtime` / `Framework/Runtime/System` |

### 什么时候用 `Instance`，什么时候用 `Modules.Get<T>()`

| 场景 | 用哪个 | 原因 |
|---|---|---|
| 运行中的游戏逻辑（窗口、控制器、业务代码） | `Modules.Get<UISystem>()` | 引擎已启动，拿不到会**明确报错并列出已注册模块**，而不是给个半初始化的对象 |
| 编辑器工具 | `UISystem.Instance` | 编辑器里没有引擎实例，`Modules` 取不到 |
| 单元测试 | `XxxSystem.Instance` | 同上，测试不启动引擎跑得更快 |
| 模块内部互相调用 | 直接字段/构造传入 | 同程序集内没必要再查一次表 |

## 5. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| Console 报缺 Package | Package Manager 装 Addressables / Input System，等解析完成后刷新 |
| Play 后直接进了 `Temp` 场景，示例场景被换掉 | 场景名没命中测试规则；改 `Bootstrap.Options.TestScenePrefixes/TestSceneContains`，或给场景改名 |
| 某个系统 `Instance` 拿到了对象但没跑起来 | 它没被注册进 `CreateModules()`。三套获取方式并存是当前已知问题 |
| 日志看不到 | 默认走 `Log`（`[Conditional]`，Release 下被编译掉），编辑器里另可在 `ScreenLogger` 面板看 |
| Addressables 报 Catalog 错误 | 保持 `GameConfig.enableHotUpdate` 关闭先用 Resources 跑通 |
| 改了 `Bootstrap.Options` 不生效 | 设置时机必须在 `BeforeSceneLoad` 之前，用 `AfterAssembliesLoaded` 钩子 |

```bash
dotnet run --project Tools/HeadlessCheck
```

它用反射加载 `dotnet build` 的产物，2 秒内验证模块访问器、Bootstrap 配置等纯托管逻辑。
覆盖范围与限制见 [Tools/HeadlessCheck/README.md](../Tools/HeadlessCheck/README.md)。

连 `dotnet build` 产物都没有时，可以先用 Roslyn 过一遍语法（需 .NET 10 SDK）：

```bash
dotnet run --project Tools/SyntaxCheck -- Unity/Gear/Assets/Gear
```

文档改完可以顺手查死链：

```bash
dotnet run --project Tools/DocsCheck -- .
```

要跑 Unity 侧的全部验证（210 个 EditMode 用例 + 架构守卫），一条命令：

```powershell
powershell -ExecutionPolicy Bypass -File Tools/unity-verify.ps1   # 或 pwsh Tools/unity-verify.ps1
```

编辑器开着时它会直接退出并提示——批量模式需要独占工程。日志与测试报告落在
`Unity/Gear/Temp/verify/`。
