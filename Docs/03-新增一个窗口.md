# 03 · 新增一个窗口

> 先确认该用哪套 UI：全屏菜单/表单类建议 UI Toolkit，3D 跟随类用 UGUI。
> 决策表与依据见 [UI系统-现状评估与演进方案](archive/UI系统-现状评估与演进方案.md)。

一个 UI 窗口由三部分组成：**一个 Controller 脚本** + **一个 Prefab** + **一个窗口 Id**（控制器上的 `[UIWindow]`）。

## 1. 生成骨架

菜单 `Gear → 内容 → 生成 UI 窗口`（`Framework/Runtime/System/UISystem/Editor/CreateUIPlane.cs`）。

它会生成三样东西：

| 产物 | 默认位置 |
|---|---|
| Controller 脚本 | `Assets/Gear/GenerateScript/UI/UIPlane/<类名>.cs` |
| 窗口 Prefab | `Assets/Gear/Resources/Prefabs/UIs/<名字>.prefab` |
| 预览场景 | `Assets/Gear/Editor/UIScenes/<名字>.unity` |

三个路径在窗口里都能改。**Prefab 的存放位置有约束**：必须在 `Resources/Prefabs/UIs/` 下，
因为同步加载走的是 `ResourcesSystem.InstantiateAsset(Config.UIPath + name)`，而 `Config.UIPath = "Prefabs/UIs/"`。

生成的 Controller 长这样：

```csharp
public class MyWindow : UIController
{
    public override void OnOpen()
    {
        base.OnOpen();
        // 与参数无关的初始化放这里；需要参数请实现 IWindowArgsReceiver<T>（见第 5 节）
    }
}
```

`UIController` 是窗口基类，`OnOpen()` 是唯一必须关心的生命周期回调（**不再带参数**）。

## 2. Prefab 上挂什么

窗口 Prefab 根节点必须有 `UIWindowAsset` 组件，它决定窗口挂到哪个层级：

| `panelType` | 挂到 | 适合 |
|---|---|---|
| `MainUI` | `mainUIRoot` | 主界面（常驻、最底层） |
| `NormalUI` | `normalUIRoot` | 普通弹窗（默认值） |
| `HeadInfoUI` | `headInfoUIRoot` | 血条、飘字这类跟随信息 |
| `TipsUI` | `tipsUIRoot` | Toast / 提示（最上层） |

其它字段：

- `panelSize`：预留字段（`SmallPanel` / `SinglePanel` / `FullScreen`），**当前没有运行时消费者**，
  不会自动关闭 Main Camera；需要全屏档请在业务层自行处理（后续要么实现、要么从字段与文档里移除）；
- `isHiddenWhenLeaveScene`：切场景时是否自动隐藏；
- `groupName`：批量关闭时按组操作。

## 3. 声明窗口 Id（不再需要 `UINames`）

> `UINames` 常量表已删除。窗口 Id 现在只有两个来源，二者等价：
> - `[UIWindow("MyWindowUIPlane")]` 的 `Id`（推荐，可读、可配层级/模态/池化）
> - 类名（`nameof(MyWindowUIPlane)`，没写特性时的回退）

```csharp
[UIWindow("MyWindowUIPlane", Layer = PanelType.NormalUI)]
public sealed class MyWindowUIPlane : UIController { }

// 取 Id（编译期、零分配）
string id = nameof(MyWindowUIPlane);
string id2 = UISystem.GetWindowId<MyWindowUIPlane>();   // 读特性，二者一致
```

**必备约定**：Prefab 文件名必须与 Id 完全一致（不带 `.prefab`）—— 加载就是按 Id 拼路径。


## 3.5 声明式窗口（推荐，2026-10 新增）

在控制器类上声明一次，窗口身份/层级/模态/池化就不再依赖"资源名 = 类名 = 预制体名"的巧合：

```csharp
[UIWindow("ShopUI", Layer = PanelType.NormalUI, Modal = false, Pooled = true)]
public sealed class ShopUI : UIController, IWindowArgsReceiver<ShopArgs>
{
    public void OnWindowArgs(ShopArgs args) { /* 强类型参数 */ }
}
```

| 特性参数 | 作用 | 不写时 |
|---|---|---|
| `Id` | 窗口标识（同时是资源名） | 回退类名（老窗口零改动） |
| `Layer` | 层级 | 仍读预制体上的 `UIWindowAsset.panelType` |
| `Modal` | 是否模态（供返回键/遮罩使用） | `false` |
| `Pooled` | 是否池化复用 | `false`（池化只有这一个来源） |

- 元数据由 `UIWindowCatalog` 收集，`UISystem.Init` 时预热一次，之后按 Id/类型查询**零反射**。
- 现有 3 个窗口（Popup / StartGame / Terminal）已经声明，行为不变（层级与预制体一致）。
- `UISystem.GetWindowId<ShopUI>()` 与 `nameof(ShopUI)` 等价；写特性时以特性里的 Id 为准。

## 4. 打开与关闭

```csharp
// 推荐：异步（Addressables 优先，失败自动降级 Resources）
await UISystem.Instance.OpenWindowAsync<MyWindowUIPlane, MyArgs>(new MyArgs(...));

// 同步：只走 Resources，WebGL 也能用
// 同步开窗已收进 internal：请统一用异步（Addressables 双轨）

// 其它
UISystem.Instance.CloseWindow(nameof(MyWindowUIPlane));
UIRouter.Close(nameof(MyWindowUIPlane));   // 或再 PushAsync 一次做"切换"
bool open = UISystem.Instance.IsOpen<MyWindowUIPlane>();
```

**为什么优先用异步**：同步路径只能走 `Resources`，因为 Addressables 没有真正的同步加载，
WebGL 更不支持 `WaitForCompletion`。异步路径会先试 Addressables，失败再降级 Resources——
热更新资源和内嵌资源都能覆盖。

还有一个坑（内部实现细节）：同名窗口正在异步加载时，内部的同步 `LoadWindow` 会**返回 null 并打警告**，
因为两条路径同时实例化会导致 `uiStateCache` 键冲突。看到这条警告就说明调用方该改成 `await`。

## 5. 传参（强类型）

参数不再走位置数组，而是声明成一个类型：

```csharp
// 1) 声明参数类型
public readonly record struct ShopArgs(string Category, int Page) : IWindowArgs;

// 2) 窗口实现接收接口
public sealed class ShopUI : UIController, IWindowArgsReceiver<ShopArgs>
{
    public void OnWindowArgs(ShopArgs args) { /* 改字段编译期就报错 */ }
}

// 3) 打开
await UISystem.Instance.OpenWindowAsync<ShopUI, ShopArgs>(new ShopArgs("weapon", 1));
// 需要返回键关闭时走导航栈
await UIRouter.PushAsync<ShopUI, ShopArgs>(new ShopArgs("weapon", 1));
```

窗口实现 `IWindowArgsReceiver<T>` 才会收到参数；**没实现也不报错**，参数被忽略（派发处记 Debug 日志）。
`OnOpen()` 本身不带参数，适合做与参数无关的界面初始化。
给已打开窗口补发参数用 `SendWindowArgsAsync`（窗口未打开会先加载再派发）。

## 5.5 导航栈与返回键（2026-10 新增）

"打开/关闭"之外补了"怎么走"：`UIRouter` 维护一个窗口栈，返回键自动接。

```csharp
await UIRouter.PushAsync<ShopUI, ShopArgs>(new ShopArgs("weapon", 1));

UIRouter.CanGoBack;    // 还有没有可返回的窗口（导航栈或模态栈）
UIRouter.Depth;        // 导航栈深度
UIRouter.Back();       // 优先关闭最上层模态，其次关闭导航栈顶
```

- **ESC / 手柄 B 自动生效**：`UIInputSystem` 的焦点域没消费取消键时才会回退到"返回"，
  文本输入框正在编辑时按 ESC 会先退出编辑，不会误关窗口（2026-10-31 修复：此前只拦了导航、没拦 Cancel）。
- **模态优先**：模态窗口不一定通过 `PushAsync` 打开，因此 `Back()` 先检查模态栈，避免关掉被模态遮住的窗口。
- **栈只记录通过 `PushAsync` 打开的窗口**；用 `UISystem.CloseWindow` 直接关掉的窗口会通过
  `OnCloseSubject` 自动从栈里摘除，不会留下"点了返回却关了个已关闭窗口"的幽灵项。
- 栈是纯 C# 的 `UINavigationStack`，不依赖 Unity，已有 HeadlessCheck 用例覆盖（压栈/去重/弹栈/摘除）。
### 5.6 等窗口返回结果（2026-10 新增）

"打开一个选择器，等它告诉我选了什么"——不用再回调塞参数：

```csharp
// 打开并等待
var result = await UIRouter.PushForResultAsync<ShopUI, ShopArgs, int>(new ShopArgs("weapon", 1));
if (result.HasValue) Use(result.Value);

// 窗口里回传（会关闭栈顶）
UIRouter.CloseWithResult(selectedIndex);
```

| 结局 | `HasValue` |
|---|---|
| 窗口调 `CloseWithResult(...)` | `true` |
| 窗口被直接关闭（X / 场景切换） | `false`（视为取消，调用方不会永久等待） |
| 窗口加载失败 | `false`（立即返回） |

同一窗口同时只允许一个等待者；重复发起会被忽略并打警告。结果类型不符也会按取消处理并告警。
### 5.7 模态窗口（2026-10 新增）

声明 `Modal = true` 的窗口打开后，**下层窗口自动失去交互**，关闭后按记录的原值还原：

```csharp
[UIWindow("ConfirmUI", Layer = PanelType.TipsUI, Modal = true)]
public sealed class ConfirmUI : UIController { }

UIRouter.DimBackground = true;   // 可选：同时变暗下层（默认只阻断交互，不动视觉）
UIRouter.DimAlpha = 0.6f;
```

- **不需要改预制体**：缺 `CanvasGroup` 的窗口在运行时补一个，`interactable` 与 `alpha` 都会还原，不覆盖美术配置；
- **支持嵌套**：只有最上层模态可交互，下层模态与普通窗口一起被阻断；
- 模态关闭后按"还剩几层模态"重算，不会误放开下层模态；
- `UIRouter.HasModal` / `ModalDepth` 可用于判断"当前是否在模态里"（比如屏蔽快捷键）。

## 6. 窗口复用的边界

`UISystem` 对窗口做对象池复用，**两个条件同时为真**才池化：

```csharp
bool enableWindowPool = true;                                  // 总开关（UISystem.cs）
[UIWindow("ShopUI", Pooled = true)]                            // 推荐：声明在窗口类上
```

默认**谁都不池化**，关闭即销毁。只有 `enableWindowPool` 开启 **且** 窗口声明了 `Pooled = true`，
关闭时才会回池、下次打开复用（代码是 `enableWindowPool && descriptor.Pooled`）。

另外，`[UIWindow(Static = true)]` 的窗口关闭时既不销毁也不入池，实例常驻、下次直接复用（适合 HUD/启动界面）。

不要指望"所有窗口都会被池化"：如果你的窗口持有大量纹理或订阅，复用反而更容易泄漏，
让它在关闭时销毁更安全。
