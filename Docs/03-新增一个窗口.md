# 03 · 新增一个窗口

> 先确认该用哪套 UI：全屏菜单/表单类建议 UI Toolkit，3D 跟随类用 UGUI。
> 决策表与依据见 [UI系统-现状评估与演进方案](archive/UI系统-现状评估与演进方案.md)。

一个 UI 窗口由三部分组成：**一个 Controller 脚本** + **一个 Prefab** + **一个常量名**。

## 1. 生成骨架

菜单 `ReunionMovement → 内容 → 生成 UI 窗口`（`Core/System/UISystem/Editor/CreateUIPlane.cs`）。

它会生成三样东西：

| 产物 | 默认位置 |
|---|---|
| Controller 脚本 | `Assets/ReunionMovement/GenerateScript/UI/UIPlane/<类名>.cs` |
| 窗口 Prefab | `Assets/ReunionMovement/Resources/Prefabs/UIs/<名字>.prefab` |
| 预览场景 | `Assets/ReunionMovement/Editor/UIScenes/<名字>.unity` |

三个路径在窗口里都能改。**Prefab 的存放位置有约束**：必须在 `Resources/Prefabs/UIs/` 下，
因为同步加载走的是 `ResourcesSystem.InstantiateAsset(Config.UIPath + name)`，而 `Config.UIPath = "Prefabs/UIs/"`。

生成的 Controller 长这样：

```csharp
public class MyWindow : UIController
{
    public override void OnOpen(params object[] args)
    {
        base.OnOpen(args);
        // args 就是 OpenWindow(name, a, b) 传进来的 a、b
    }
}
```

`UIController` 是窗口基类，`OnOpen` 是唯一必须关心的生命周期回调。

## 2. Prefab 上挂什么

窗口 Prefab 根节点必须有 `UIWindowAsset` 组件，它决定窗口挂到哪个层级：

| `panelType` | 挂到 | 适合 |
|---|---|---|
| `MainUI` | `mainUIRoot` | 主界面（常驻、最底层） |
| `NormalUI` | `normalUIRoot` | 普通弹窗（默认值） |
| `HeadInfoUI` | `headInfoUIRoot` | 血条、飘字这类跟随信息 |
| `TipsUI` | `tipsUIRoot` | Toast / 提示（最上层） |

其它字段：

- `panelSize`：`SmallPanel` / `SinglePanel` / `FullScreen`——非全屏、遮挡 80%、全屏三档，
  全屏档可以关掉 Main Camera 省开销；
- `isHiddenWhenLeaveScene`：切场景时是否自动隐藏；
- `groupName`：批量关闭时按组操作。

## 3. 加进 `UINames`

```csharp
// Core/System/UISystem/UINames.cs
public static class UINames
{
    public const string MyWindow = "MyWindowUIPlane";
}
```

名字必须**和 Prefab 文件名完全一致**（不带 `.prefab`），因为加载就是按这个名字拼路径的。
用常量而不是字符串，一是防拼错，二是避免字符串 GC。

## 3.5 声明式窗口（推荐，2026-10 新增）

在控制器类上声明一次，窗口身份/层级/模态/池化就不再依赖"资源名 = 类名 = 预制体名"的巧合：

```csharp
[UIWindow("ShopUI", Layer = PanelType.NormalUI, Modal = false, Pooled = true)]
public sealed class ShopUI : UIController, IWindowArgsReceiver<ShopArgs>
{
    public void OnWindowArgs(ShopArgs args) { /* 强类型参数 */ }
}
```

| 特性参数 | 作用 | 不写时 |
|---|---|---|
| `Id` | 窗口标识（同时是资源名） | 回退类名（老窗口零改动） |
| `Layer` | 层级 | 仍读预制体上的 `UIWindowAsset.panelType` |
| `Modal` | 是否模态（供返回键/遮罩使用） | `false` |
| `Pooled` | 是否池化复用 | `false`（也不用再往 `poolableWindowNames` 手写） |

- 元数据由 `UIWindowCatalog` 收集，`UISystem.Init` 时预热一次，之后按 Id/类型查询**零反射**。
- 现有 3 个窗口（Popup / StartGame / Terminal）已经声明，行为不变（层级与预制体一致）。
- 只声明了特性、没有 `UINames` 常量也能用：`UISystem.GetWindowId<ShopUI>()` 就是它的 Id。

## 4. 打开与关闭

```csharp
// 推荐：异步（Addressables 优先，失败自动降级 Resources）
await UISystem.Instance.OpenWindowAsync(UINames.MyWindow, someData);

// 同步：只走 Resources，WebGL 也能用
UISystem.Instance.OpenWindow(UINames.MyWindow);

// 其它
UISystem.Instance.CloseWindow(UINames.MyWindow);
UISystem.Instance.ToggleWindow(UINames.MyWindow);
bool open = UISystem.Instance.IsOpen(UINames.MyWindow);
```

**为什么优先用异步**：同步路径只能走 `Resources`，因为 Addressables 没有真正的同步加载，
WebGL 更不支持 `WaitForCompletion`。异步路径会先试 Addressables，失败再降级 Resources——
热更新资源和内嵌资源都能覆盖。

还有一个坑：如果同名窗口正在异步加载，此时调同步的 `LoadWindow` 会**返回 null 并打警告**，
因为两条路径同时实例化会导致 `uiStateCache` 键冲突。看到这条警告就说明调用方该改成 `await`。

## 5. 传参

参数直接透给 `OnOpen`：

```csharp
await UISystem.Instance.OpenWindowAsync(UINames.MyWindow, 42, "hello");

// MyWindow.OnOpen
public override void OnOpen(params object[] args)
{
    base.OnOpen(args);
    int id = (int)args[0];
    string text = (string)args[1];
}
```

`params object[]` 会装箱。高频打开的小窗口建议传一个结构体/类，而不是一堆值类型参数。

**推荐改成强类型参数**（2026-10 新增，旧写法继续可用）：

```csharp
// 1) 声明参数类型
public readonly record struct ShopArgs(string Category, int Page) : IWindowArgs;

// 2) 窗口实现接收接口
public sealed class ShopUI : UIController, IWindowArgsReceiver<ShopArgs>
{
    public void OnWindowArgs(ShopArgs args) { /* 改字段编译期就报错 */ }
}

// 3) 打开
await UISystem.Instance.OpenWindowAsync<ShopUI, ShopArgs>(new ShopArgs("weapon", 1));
```

窗口实现 `IWindowArgsReceiver<T>` 才会收到强类型参数；`OnOpen(object[])` 仍会照常调用一次，
所以同一个窗口可以两种方式并存、迁移可以逐个来。

## 5.5 导航栈与返回键（2026-10 新增）

"打开/关闭"之外补了"怎么走"：`UIRouter` 维护一个窗口栈，返回键自动接。

```csharp
await UIRouter.PushAsync<ShopUI, ShopArgs>(new ShopArgs("weapon", 1));

UIRouter.CanGoBack;    // 还有没有可返回的窗口
UIRouter.Depth;        // 栈深度
UIRouter.Back();       // 关闭栈顶并从栈里移除
```

- **ESC / 手柄 B 自动生效**：`UIInputSystem` 的焦点域没消费取消键时才会回退到"关闭栈顶"，
  所以输入框正在编辑时按 ESC 先是退出编辑，不会误关窗口。
- **栈只记录通过 `PushAsync` 打开的窗口**；用 `UISystem.CloseWindow` 直接关掉的窗口会通过
  `OnCloseSubject` 自动从栈里摘除，不会留下"点了返回却关了个已关闭窗口"的幽灵项。
- 栈是纯 C# 的 `UINavigationStack`，不依赖 Unity，已有 HeadlessCheck 用例覆盖（压栈/去重/弹栈/摘除）。
### 5.6 等窗口返回结果（2026-10 新增）

"打开一个选择器，等它告诉我选了什么"——不用再回调塞参数：

```csharp
// 打开并等待
var result = await UIRouter.PushForResultAsync<ShopUI, ShopArgs, int>(new ShopArgs("weapon", 1));
if (result.HasValue) Use(result.Value);

// 窗口里回传（会关闭栈顶）
UIRouter.CloseWithResult(selectedIndex);
```

| 结局 | `HasValue` |
|---|---|
| 窗口调 `CloseWithResult(...)` | `true` |
| 窗口被直接关闭（X / 场景切换） | `false`（视为取消，调用方不会永久等待） |
| 窗口加载失败 | `false`（立即返回） |

同一窗口同时只允许一个等待者；重复发起会被忽略并打警告。结果类型不符也会按取消处理并告警。

## 6. 窗口复用的边界

`UISystem` 对窗口做对象池复用，由两个来源控制（任一为真即池化）：

```csharp
bool enableWindowPool = true;                                  // 总开关（UISystem.cs）
[UIWindow("ShopUI", Pooled = true)]                            // 推荐：声明在窗口类上
public readonly List<string> poolableWindowNames = ...;         // 老方式：手写白名单（保留兼容）
```

默认**谁都不池化**，关闭即销毁。只有声明 `Pooled = true` 或加进老白名单，关闭时才会回池、下次打开复用。

不要指望"所有窗口都会被池化"：如果你的窗口持有大量纹理或订阅，复用反而更容易泄漏，
让它在关闭时销毁更安全。

1. Play，`OpenWindowAsync` 能打开，`panelType` 对应的层级正确；
2. 连续打开/关闭 20 次，Hierarchy 里不残留节点（池化窗口除外）；
3. 切场景后，`isHiddenWhenLeaveScene = true` 的窗口自动隐藏；
4. 走一遍 `ReunionMovement → 开发 → 守卫 → 运行架构检查`，新脚本不要超过 600 行。
