# 02 · 新增一个系统

读这篇之前请先看 [01-架构总览](01-架构总览.md) 的模块表，知道现有 14 个模块各自负责什么。

## 最小可用版本

一个系统 = 一个类 + 一个 `[ModuleOrder]` + 一行注册。

```csharp
using Cysharp.Threading.Tasks;
using Astray.Framework.Runtime.Base;

namespace Astray.Framework.Runtime.Example
{
    [ModuleOrder(85, typeof(EventMessageSystem))]   // 85 = 排在 TimerMgr(80) 之后、UISystem(90) 之前
    public class ExampleSystem : ICustomSystem
    {
        public double InitProgress { get; private set; }

        public async UniTask Init()
        {
            InitProgress = 0;
            // 这里做异步初始化：读配置、加载资源、连服务器…
            InitProgress = 100;
        }
    }
}
```

`ICustomSystem` 只要求 `Init()` 和 `InitProgress`，其余能力按需叠加：

> 也可以直接用现成模板：菜单 `Astray → 工具箱` → 「复制模块模板」，
> 模板文件是 `Documentation/CustomSystem.cs.txt`，包含 `Lazy<T>` 单例、`[ModuleOrder]` 和三个接口的骨架。

| 需要什么 | 额外实现 | 方法 | 谁调用 |
|---|---|---|---|
| 每帧更新 | `ISystemUpdatable` | `Update(float logicTime, float realTime)` | `GameEngine.OnUpdate` |
| 固定帧更新 | `ISystemFixedUpdatable` | `FixedUpdate(float fixedDeltaTime)` | `GameEngine.OnFixedUpdate` |
| 渲染前更新 | `ISystemLateUpdatable` | `LateUpdate(float deltaTime, float unscaledDeltaTime)` | `GameEngine.OnLateUpdate` |
| 清理 | `ISystemDisposable` | `Clear()` | `GameEngine.ClearModuleData` / `Dispose` |

`logicTime` 与 `realTime` 的区别很重要：暂停时 `Time.timeScale = 0`，`logicTime` 归零但 `realTime` 照常走。
UI 动画、网络心跳这类"暂停了也得动"的逻辑必须用 `realTime`。

## 声明顺序与依赖

```csharp
[ModuleOrder(85, typeof(EventMessageSystem), typeof(ResourcesSystem))]
```

第一个参数是**排序权重**（越小越先 `Init`），后面是**依赖的类型**。

为什么必须有这个特性：

- 没有它，初始化顺序就等于 `CreateModules()` 里的书写位置——加一行、删一行都可能悄悄改掉启动顺序；
- 有了它，顺序由数据决定，`ModuleCatalog` 启动时会做拓扑排序并**校验**四类错误：
  重复注册、缺依赖、自己依赖自己、成环。

现有顺序（见 `Core/StartGame.cs`）：

| Order | 系统 | Order | 系统 |
|---|---|---|---|
| 10 | `ResourcesSystem` | 90 | `UISystem` |
| 20 | `AddressableSystem` | 100 | `UIInputSystem` |
| 30 | `SceneSystem` | 110 | `UIToolkitSystem` |
| 40 | `EventMessageSystem` | 120 | `TerminalSystem` |
| 50 | `LanguagesSystem` | 130 | `NetworkMgr` |
| 60 | `PauseSystem` | 140 | `HttpMgr` |
| 70 | `SoundSystem` | | |
| 80 | `TimerMgr` | | |

新模块挑一个不冲突的数字即可，间隔 10 只是习惯，不影响正确性。

## 注册

在 `Core/StartGame.cs` 的 `CreateModules()` 里加一行：

```csharp
modules.Add(ExampleSystem.Instance);   // 85 示例系统
```

注意这里是"**注册哪些**"，不是"谁先谁后"——顺序由 `[ModuleOrder]` 决定。

## 获取实例

```csharp
// 运行时（引擎已启动）：拿不到会抛异常，并列出已注册的模块
var example = Modules.Get<ExampleSystem>();

// 编辑器工具、单元测试：引擎没启动也能拿到
var example = ExampleSystem.Instance;
```

`Modules.Get<T>()` 抛的异常里带着**已注册模块清单**，比 `NullReferenceException` 好排查得多。

单例的写法沿用仓库现有风格：

```csharp
private static readonly Lazy<ExampleSystem> instance = new(() => new ExampleSystem());
public static ExampleSystem Instance => instance.Value;
```

## 验证

1. **看启动日志**：Play 之后 Console 里应有一行
   `模块顺序: ResourcesSystem(10) → … → ExampleSystem(85) → …`
2. **跑测试**：`Tests/ModuleCatalogTests.cs` 里有排序/环/缺依赖的现成写法，照着加一条
3. **过守卫**：菜单 `Astray → 开发 → 守卫 → 运行架构检查`
   - 新文件超过 600 行会被拦（守卫会提示加进基线，但正确做法是拆）
   - 忘了写 `[ModuleOrder]` 会被拦

## 清理要幂等

`Clear()` 可能被调用多次（切账号、引擎重建），必须能重复执行：

```csharp
public void Clear()
{
    // 1. 先还原全局状态（timeScale、AudioListener、Cursor…）
    // 2. 再释放订阅与资源，并置 null
    // 3. 最后把 isInited 设为 false
}
```

`PauseSystem.Clear()` 是最完整的参考：它还原 `timeScale`、恢复 `AudioListener`、清空暂停原因、`Dispose` 掉 R3 对象并置 `null`。
漏掉第 1 步的后果是"下一局一开始就卡死"，漏掉第 2 步的后果是订阅者泄漏。

## 反模式

| 别这样 | 为什么 |
|---|---|
| 在模块里再开一个 `MonoBehaviour` 自己 Update | 会和 `GameEngineDriver` 形成双驱动，暂停/时间缩放语义直接乱掉 |
| 用 `FindObjectOfType` 找别的模块 | 启动顺序不保证对象已创建；用 `[ModuleOrder]` 声明依赖 + 构造注入 |
| 在 `Init()` 里 `while` 等某个条件 | 会卡住整个启动链；用异步加载或事件回调 |
| 把业务逻辑写进模块 | 模块只负责"能力"，业务属于 `GameEntry.OnGameStartAsync` 之后 |
