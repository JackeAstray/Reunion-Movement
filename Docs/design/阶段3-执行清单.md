## 二、与原计划的偏差（重要）

**原计划第 1 步"先建两个 asmdef、不动目录"不可行**：asmdef 的作用域是"它所在目录及其全部子目录"，而 `Utils/Util` 与 `Utils/UI` 是**兄弟目录**，一个 asmdef 盖不住两者。要么先移动到一个共同父目录，要么拆成 3 个程序集。

因此正确顺序是：**移动目录 → 建 asmdef → 改命名空间**（原计划把移动放在第 3 步）。

## 三、已完成的可行性验证

按目标划分（`Util` + `UI` → Utilities，其余 → Framework.Modules）用 Unity 自己的 rsp 参数做了两次独立编译：

```
Utilities（76 文件，排除各目录下 Editor/）        → 0 error
Framework.Modules（101 文件，引用 Utilities）      → 0 error
```

结论：**两个方向没有循环依赖**，拆分在编译层面可行。（`Base` 里的 `InternalsVisibleTo("ReunionMovement.Utils")` 只授予 setter，拆分后读侧不需要它。）

## 五、执行步骤（严格按序，每步一个提交）

### 步骤 1：移动目录（命名空间不动）

```bash
# .cs 与 .meta 必须同进同出；git mv 整目录会一起移动
git mv Unity/ReunionMovement/Assets/ReunionMovement/Utils/Util \
       Unity/ReunionMovement/Assets/ReunionMovement/Utilities
git mv Unity/ReunionMovement/Assets/ReunionMovement/Utils/UI \
       Unity/ReunionMovement/Assets/ReunionMovement/Utilities/UI
# 其余 Utils/* → Framework/Modules/*
git mv .../Utils/Network .../Framework/Modules/Network
...
```

**验收**：`pwsh Tools/unity-verify.ps1` 全绿（Unity 会重新导入；GUID 随 `.meta` 保留，prefab/scene 引用不受影响）。

> 中间态说明：此时目录已改名、命名空间仍是 `ReunionMovement.Common.Util.*`。这是有意的过渡态，只应存在一个提交的时间。

### 步骤 2：建 asmdef

- `Utilities/ReunionMovement.Utilities.asmdef`（rootNamespace `ReunionMovement.Utilities`）
- `Framework/Modules/ReunionMovement.Framework.Modules.asmdef`（rootNamespace `ReunionMovement.Framework.Modules`）
- 删除 `ReunionMovement.Utils.asmdef`
- 引用方 asmdef 改名（按**名字**引用，共 3 处：`Core`、`Tests`、若干 Editor 程序集）

**验收**：同上；这一步 `.cs` 一个字节不改。

### 步骤 3：改命名空间

按归档清单的映射表逐个改，**一次一个命名空间、改完立刻编译 + 提交**。
不要正则批量替换 `using`（`ReunionMovement.Core` 同时出现在 `using` 和字符串里）。

**验收**：`pwsh Tools/unity-verify.ps1` + 菜单「Addressables → 校验地址」无缺失。
