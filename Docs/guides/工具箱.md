# Gear 工具箱

菜单 `Gear → 工具箱`（优先级最高，也是唯一的高频入口）。

窗口分七个 Tab，每个 Tab 只做一件事：

| Tab | 用途 | 会不会改工程 |
|---|---|---|
| **概览** | 状态卡片（错误/提醒/通过）+ 按严重度排的「下一步」+ 快速开始 | 只读 |
| **检查** | 按类别分组的体检报告，支持搜索与复制 | 只读 |
| **模块** | 14 个模块的序号/命名空间/程序集/依赖，并静态校验序号冲突与缺失依赖 | 只读 |
| **守卫** | 六条架构规则就地运行，直接列出违规文件/系统 | 只读 |
| **工具** | 调用现有菜单项（表格 / 小功能 / 窗口生成器 / 流水线） | 需二次确认 |
| **Addressables** | 开关 + 状态（包是否安装 / 本地配置 / 结构是否齐全）+ 启用/关闭/补齐/删除 | 需二次确认 |
| **文档** | 按阅读顺序列出 `Docs/`，点一下用系统默认程序打开 | 只读 |

## 0. Addressables 页（默认关闭）

这里决定"框架要不要用 Addressables"，别的菜单都跟着它走：

- **关闭（默认）**：运行时 `AddressablesMode.Off`，全程走 Resources；不检查、也不创建任何 Addressables 数据，
  仓库里不含 `Assets/AddressableAssetsData`。迁移 / 构建 / 上传菜单在这种状态下是灰的。
- **启用**：检查 `com.unity.addressables` 是否安装 → 把 `GameConfig.enableHotUpdate` 置为 true → 按需创建 Settings / 9 分组 / 7 Label / 2 Profile。
- **关闭**只改开关，不删数据；要清理用「删除本地配置」（删 `AddressableAssetsData` 与迁移产物 `AddressableAssets`）。

装包失败或结构不齐时，状态行会直接说明缺什么，按钮也相应禁用。

## 1. 概览

打开窗口先看这里。

- 三个卡片：错误 / 提醒 / 通过的数量；
- **下一步**：按严重度取前 3 条**可处理**的问题，每条右边就是修复按钮——没有动作的问题不会出现在这里；
- **快速开始**：选示例场景直接打开、创建或定位 `GameConfig`、打开快速开始与常见陷阱文档。

## 2. 检查

检查项按类别分组：环境 / 依赖包 / 工程资产 / 配置 / Addressables / 文档。

| 检查项 | 判据 |
|---|---|
| Unity 版本 | 6000.3+ 为通过 |
| Addressables / Input System | 已安装且版本与验证版本一致为通过，版本不同给提醒 |
| 框架资产根目录、源码生成器 | 存在为通过 |
| `GameConfig` | 缺失给提醒（框架有静态默认值，可一键创建）；`enableHotUpdate` 开启时提示"首次运行建议关闭" |
| Addressables 配置 | 9 个分组 / 7 个 Label / 2 个 Profile 名称齐全为通过（**不代表远程 URL 与内容已验证**） |
| 文档 | `Docs/` 下的六篇上手文档，以及 Addressables / 打包两篇专题 |

顶部的搜索框按标题、说明、按钮文字过滤；「只看问题」会隐藏通过项；「复制报告」把当前列表写进剪贴板，方便贴到 issue。

所有检查都只读，不会安装 Package、创建配置或迁移资源。

## 3. 模块

列出所有带 `[ModuleOrder]` 的类型（当前 14 个），按序号排序，显示：

```
10  ResourcesSystem    Gear.Framework.Runtime.Resources   Gear.Framework.Runtime  依赖 —
20  AddressableSystem  Gear.Framework.Runtime.Addressable Gear.Framework.Runtime  依赖 ResourcesSystem
…
```

并做两项**静态可见**的校验：

- 序号冲突（两个模块同序号时，启动顺序取决于 `CreateModules()` 的书写位置）；
- 依赖的模块没有 `[ModuleOrder]` 或不在本工程内。

真正的启动顺序由 `ModuleCatalog` 在运行时拓扑排序，Console 会打印一行 `模块顺序: …`。这个 Tab 只是让"声明"可见。

> 模块信息是反射读出来的（`Gear.Toolbox.Editor.asmdef` 只引用 `Gear.Editor.Shared`，刻意不依赖 Runtime 程序集），所以按特性类型名匹配。

## 4. 守卫

六条规则与 CI、EditMode 测试共用同一份实现（`ArchitectureGuard`）：

| 规则 | 失败意味着 |
|---|---|
| 单文件行数 | 新文件超过 600 行，或已登记基线的文件又变大 |
| `.meta` 完整性 | 有 `.cs`/`.asmdef` 没带 `.meta`，GUID 会重新生成、引用断开 |
| asmdef 依赖方向 | 上层被下层引用（`Base → Common → Utilities → Modules → Runtime` 只能单向） |
| `.Instance` 使用点 | 新增了单例直取，应改用 `Modules.Get<T>()` |
| 模块顺序声明 | 有 `ICustomSystem` 实现没写 `[ModuleOrder]` |
| 旧命名残留 | 代码、模板或文档里还写着改名前的程序集名或目录路径 |

失败时会就地列出前 8 条违规（其余提示"详见 Console"）。首次进入该 Tab 会自动跑一次。

命令行等价物：

```bash
Unity -batchmode -quit -projectPath Unity/Gear \
      -executeMethod Gear.Editor.Guards.ArchitectureGuard.RunAllBatch
```

## 5. 工具

按钮只是调用现有菜单项，不复制工具逻辑；修改类操作都会二次确认，且编译中 / 导入中 / 构建中 / Play Mode 下会被拒绝（延迟执行前会再检查一次，不会自动重试）。

分组：资源与发布 / Addressables / 数据与辅助 / 窗口生成 / 扩展模块。

「扩展模块」区的「复制模块模板」复制的是 [CustomSystem 模板](../../Unity/Gear/Assets/Gear/Documentation/CustomSystem.cs.txt)，
模板已包含 `[ModuleOrder]`（守卫强制要求）。保存到 `Framework/Runtime/System` 下以沿用 `Gear.Framework.Runtime` 程序集，再在 `CreateModules()` 显式注册——工具箱不改启动列表。

## 6. 文档

按阅读顺序列出 `Docs/`：00 快速开始 → 01 架构总览 → 02 新增系统 → 03 新增窗口 → 04 接入自己的游戏 → 05 常见陷阱，之后是参考类文档。

查找顺序：项目根 `Docs/` → 仓库根 `Docs/` → 随包 `Documentation/Gear 使用指南.md`。
用 `.unitypackage` 引入的项目没有完整 `Docs/`，会回退到随包指南。

## 7. 菜单结构

`Gear` 一级菜单收敛为 6 项，并按**段位**固定顺序（优先级区间决定顺序，不再互相穿插）：

| 一级 | 内容 | 优先级段 |
|---|---|---|
| `工具箱` | 唯一的高频入口（七个 Tab） | 0 |
| `打包 ▸` | UPM 包（运行时 / 完整 / OpenUPM）+ `导出 .unitypackage` | 110–120 |
| `构建 ▸` | Windows / macOS / Linux / Android / WebGL / iOS | 201–206 |
| `内容 ▸` | 表格 → 脚本 / ScriptableObject / JSON、生成 UI 窗口、生成示例场景 | 301–305 |
| `Addressables ▸` | 启用 / 关闭（置顶）+ 一键流水线 + 配置 / 构建 / 迁移 / 上传 | 401–441 |
| `开发 ▸` | 守卫、第三方依赖检查、打开文件夹、碰撞器线框宏、清除截止日期、小功能 | 501–541 |

语义：**打包**＝分发产物（UPM / unitypackage），**构建**＝出 Player，**内容**＝生成资产，
**Addressables**＝可选能力（默认关闭，启用后才有意义），**开发**＝调试与诊断。

> 旧结构里 `导出 unitypackage` 是一级菜单、且和 `打包` 分开，容易误点；现在它收进 `打包` 段。
> 一级菜单顺序以后不要再靠"谁先写"决定 —— 新加的菜单请落在所属段的区间内。

## 8. 尚未在 Unity 内验收

本文描述的布局只在编译层面验证过（`dotnet build Gear.Toolbox.Editor.csproj`，0 错误）。
以下需要真机确认：

1. 七个 Tab 的间距、换行、滚动是否正常，有没有 IMGUI 异常（`Addressables` 页是新增的，Tab 栏可能偏挤）；
2. 守卫 Tab 首次进入自动运行（用了 `delayCall`，避免在 Layout 事件里改状态）是否只跑一次；
3. 模块 Tab 的「定位脚本」对 partial 类（如 `UISystem`）能否命中主文件；
4. 文档 Tab 在「项目内没有 Docs」时是否正确回退到随包指南；
5. 新菜单路径下每个菜单项都能打开对应窗口（改名后 `ExecuteMenu` 字符串是否都跟上）。
