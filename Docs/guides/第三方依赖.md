# 第三方依赖与冲突处理

> 框架为了让仓库**离线可编译**，把一批第三方库以源码/DLL 形式放在 `Plugins/` 和 `3rd/` 下。
> 接入方如果已经装了同名官方 UPM 包，就会出现**同名类型**或**同名程序集**，编译直接失败。
> 本文说明版本、冲突关系和二选一的操作方式。

## 1. 版本清单

| 组件 | 版本 | 内置位置 | 上游 | 官方 UPM 包 | 冲突风险 |
|---|---|---|---|---|---|
| UniTask | 2.5.11 | `Plugins/UniTask` | [Cysharp/UniTask](https://github.com/Cysharp/UniTask) | `com.cysharp.unitask` | **高** |
| R3 | 1.3.1 | `Plugins/R3`（DLL） | [Cysharp/R3](https://github.com/Cysharp/R3) | `com.cysharp.r3` | **高** |
| ZString | 2.6.0 | `Plugins/ZString`（DLL） | [Cysharp/ZString](https://github.com/Cysharp/ZString) | `com.cysharp.zstring` | 中 |
| DOTween | 1.0.0.0（DLL 无版本号） | `Plugins/DOTween` | [DOTween](http://dotween.demigiant.com/) | Asset Store / OpenUPM | 中 |
| Newtonsoft.Json | 3.2.2（官方包） | 不再内置（2026-10-22 已删 `Plugins/Newtonsoft.Json.dll`） | [JamesNK/Newtonsoft.Json](https://github.com/JamesNK/Newtonsoft.Json) | `com.unity.nuget.newtonsoft-json` | 已消除 |

> `SharpZipLib 1.4.2.13` 也已删除（框架内 0 处引用）。
>
> kcp2k / Telepathy / SimpleWebTransport / WebGLInput / SourceGenerator 等无官方同名 UPM 包，冲突风险低。

> UniTask 的 `UniTask.Addressables` / `UniTask.Linq` / `UniTask.DOTween` / `UniTask.TextMeshPro`
> 子程序集也随源码内置；官方 UniTask 包同样提供这些 asmdef，冲突范围与主程序集一致。

## 2. 冲突怎么发现

菜单：

```
Gear → 开发 → 检查第三方依赖冲突
```

命令行（有冲突时退出码 1）：

```powershell
Unity -batchmode -quit -projectPath Unity/Gear `
  -executeMethod Gear.EditorTools.Package.ThirdPartyDependencyChecker.CheckBatch
```

检测逻辑：`PackageInfo.GetAllRegisteredPackages()` 里出现官方包，同时 `Plugins/` 下仍存在内置副本，
就报一条冲突。它**不会**自动删文件。

## 3. 二选一

### 方案 A：接入方已装官方包（推荐）

删掉框架内的对应副本，保留官方包：

| 组件 | 删除 | 保留 |
|---|---|---|
| UniTask | `Plugins/UniTask/` | `com.cysharp.unitask` |
| R3 | `Plugins/R3/` | `com.cysharp.r3` |
| ZString | `Plugins/ZString/` | `com.cysharp.zstring` |
| Newtonsoft.Json | 已切官方包，无需操作 | `com.unity.nuget.newtonsoft-json` |
| DOTween | `Plugins/DOTween/` | 宿主自己的 DOTween（Asset Store / OpenUPM） |

> 删目录时连 `.meta` 一起删。框架的 asmdef 按名称引用 `UniTask` / `UniTask.Addressables` /
> `DOTween.Modules`，官方包提供同名程序集时不需要改代码。
>
> DOTween 的 asmdef 名称在官方分发里不一定叫 `DOTween.Modules`；删内置副本前先确认官方包
> 里有这个程序集。不确定就保留内置 DOTween，别同时装官方 DOTween。

### 方案 B：离线/自包含（当前默认）

保留 `Plugins/` 下的副本，**不要**再装官方同名包。UPM 包默认就是这个模式。
适合作品集、外包交付、不能联网拉包的项目。

### 方案 C：OpenUPM 依赖模式（已提供）

导出菜单：`Gear → 打包 → 导出 UPM 包（OpenUPM 依赖）`；
命令行：`-executeMethod Gear.EditorTools.Package.GearUpmExporter.ExportOpenUpmBatch`。

这个 profile **只把 UniTask 交给 OpenUPM**，`package.json` 声明：

```json
"com.cysharp.unitask": "2.5.11"
```

R3 / ZString 继续内置，原因不是偷懒：

- OpenUPM 的 `com.cysharp.r3` 只包含 `R3.Unity`，`R3.Unity.asmdef` 用 `precompiledReferences`
  引用 `R3.dll`，而包内不带核心 `R3.dll`；直接装会报 `Observable<>` / `Subject<>` 找不到。
- `com.cysharp.zstring` 是 asmdef 程序集，所有使用方必须在 asmdef 里显式引用 `ZString`；
  当前框架用内置 DLL（自动引用），两种模式不能共用同一份 asmdef。

UniTask 在 **OpenUPM**，不在 Unity 官方 registry。宿主需要先在 `Packages/manifest.json` 加：

```json
"scopedRegistries": [
  {
    "name": "OpenUPM",
    "url": "https://package.openupm.com",
    "scopes": [ "com.cysharp" ]
  }
]
```

然后再安装 `com.jackeastray.gear`。UniTask 版本已在 2026-10-22 通过 OpenUPM 确认（2.5.11）。
DOTween 仍内置（没有稳定的 Unity registry 包）；Newtonsoft 走 Unity 官方包。

## 4. 已知的“半冲突”

- **`ICSharpCode.SharpZipLib.dll`**：已删除（框架 0 引用）。
- **DOTween**：`Plugins/DOTween` 里同时有 `DOTween.dll` 和 `Modules/*.cs`；
  `DOTween.Modules.asmdef` 是本仓库补的（此前 `UniTask.DOTween` 引用了一个不存在的程序集名）。
  如果宿主用官方 DOTween，确认其 asmdef 名称后再删内置副本。
- **UniTask 版本**：内置 2.5.11 带 Unity 6 的兼容修改。升级前先按上游 diff 核对，
  不要直接覆盖整个目录。

## 5. 验收

```powershell
# 1. 无冲突（当前仓库应通过）
Unity -batchmode -quit -projectPath Unity/Gear `
  -executeMethod Gear.EditorTools.Package.ThirdPartyDependencyChecker.CheckBatch

# 2. 人为制造冲突（可选）
#    在 Packages/manifest.json 加 "com.cysharp.unitask": "2.5.11"，
#    保留 Plugins/UniTask，再跑上面的命令，应退出 1 并在 Console 看到冲突说明。
```
