# 便捷性与可移植性评估

> 评估对象：`Reunion-Movement` @ `41830fc`（2026-10-22）
> 评估范围：**"离开这个仓库之后"** 的三件事 —— 调用、跨平台、插件便携性。
> 方法：只读代码 / 工程配置 / 文档 + 静态统计；标"需实机"的条目没有在 Unity 里跑构建。
> 不重复 [重构方案](重构方案.md) 已经解决的内部质量问题（分层、模块契约、守卫、测试）。
> **落地进度**：§1.1 / §1.2 / §1.6 / §1.7 / §2.1-§2.4 / §2.10 / §3.1 / §3.2 / §3.3 已实现；§2.8 已加 license-check + CI jobs（Unity job 待 secret）；
> iOS 链接与 IL2CPP High stripping 仍需真机验证；其余待做。

## 0. 一页结论

框架内部已经"很工程化"：26 个 asmdef、模块拓扑排序、16 个测试文件、5 条架构守卫、六篇上手文档。
真正的短板不在"代码写得对不对"，而在 **"把它搬到另一个工程里，还能不能顺利用"**。

| 维度 | 现在的水平 | 最大阻塞 | 严重度 |
|---|---|---|---|
| 调用 | 入口可插拔、模块有依赖校验 | 没有入口声明时会**自动接管宿主工程**；`BootstrapOptions` 没有入口字段；三套取实例方式 | 高 |
| 跨平台 | WebGL 适配细（线程 / 网络 / 全屏都做了守卫） | **没有任何构建脚本**；iOS 触觉只有 P/Invoke 没有原生实现；Android 缺 `VIBRATE` 权限；没有 `link.xml` | 高 |
| 插件便携 | 第三方版本齐全、asmdef 分层清晰 | **没有 UPM 包**；第三方 vendored 且程序集重名；编辑器工具写死 `Assets/ReunionMovement`；129 MB 字体 | 高 |

**如果只做三件事**：

1. **让框架不劫持宿主**（P0，约 0.5 人日）——没有声明入口时不要回退 `StartGame`，并给 `BootstrapOptions` 加 `Entry`。
2. **出一条可版本化的 UPM 包**（P0，约 1.5 人日）——先做 `ReunionPaths`，再让导出器生成 `com.reunion.movement`，用 git URL 安装。
3. **把移动端补成"能出包"或明确"不支持"**（P0，约 1 人日）——iOS 触觉原生实现、Android `VIBRATE`、`link.xml`。

## 1. 调用：从"能跑"到"好接"

### 1.1 P0 · 没有入口声明时，框架会接管宿主工程

> 状态：✅ 已实现（2026-10-22）。示例入口已移到不进包的 `Game/StartGameEntry.cs`，框架程序集不再声明入口；
> 在包安装的宿主工程里，`Bootstrap.ResolveEntry` 找不到入口会返回 null 并报错，只有显式打开
> `AllowBuiltInEntryFallback` 才用内置 `StartGame`。

这是"把框架放进已有项目"时第一个会踩的坑，也是本文最建议先修的一条。

**改造前的机制**：

1. `Bootstrap.OnBeforeSceneLoad()` 在任何包含该程序集的工程里都会于 `BeforeSceneLoad` 执行（`Core/Bootstrap.cs:96`）。
2. `ResolveEntry()` 先找 `[assembly: ReunionGameEntry]`；找不到就用 `new StartGame()`（`Core/Bootstrap.cs:220-228`）。
3. `StartGame.OnGameStartAsync()` 加载 `Temp` 场景并打开启动界面（`Core/StartGame.cs:142-145`）。
4. `GameEntryResolver` 只跳过 `Unity/System/...` 前缀，**不跳过 `ReunionMovement.*`**，所以旧版框架自带的 `[assembly: ReunionGameEntry(typeof(StartGame))]`（原 `Core/Bootstrap.cs:13`）在宿主工程里同样生效。现已移到不进包的 `Game/StartGameEntry.cs`，框架程序集不再声明入口。

**复现**：新建空工程 → 只导入 `Assets/ReunionMovement` → 打开宿主自己的场景 → Play。
结果是宿主场景被替换成 `Temp`（或报"场景未加入 Build Settings"），并弹出框架的启动界面。

**建议**（二选一，推荐 A）：

```csharp
// A. 去掉隐式回退：没有声明就明确报错，不替用户做决定
private static GameEntry ResolveEntry()
{
    if (Options.Entry != null) return Options.Entry;

    var declared = GameEntryResolver.CreateEntry();
    if (declared != null) return declared;

    if (!Options.AllowBuiltInEntryFallback)
    {
        Log.Error("[Bootstrap] 未声明入口。请加 [assembly: ReunionGameEntry(typeof(MyGameEntry))]，" +
                  "或设置 Bootstrap.Options.Entry。内置 StartGame 只在示例工程里使用。");
        return null;
    }
    return new StartGame();
}
```

```csharp
// B. 保守版：保留回退，但只允许显式开启
public bool AllowBuiltInEntryFallback = false;   // BootstrapOptions
public IGameEntry Entry;                          // 你的入口实例
```

> 本仓库自己在 `Core/Bootstrap.cs:13` 声明了 `StartGame`，所以改成 A 之后仓库内的 Play 流程不受影响；
> 受影响的是"导入了包但没声明入口"的宿主工程 —— 这正是要修的。

### 1.2 P1 · 入口只能靠程序集特性

> 状态：✅ 已实现（2026-10-22）。`BootstrapOptions.Entry` 已加入，优先级高于程序集声明。

改造前 `Docs/04-接入自己的游戏.md` 明确写着"`BootstrapOptions` 里没有入口字段"，入口只能写程序集特性或手动 `Disable()` + `StartAsync()`。
现在 `BootstrapOptions.Entry` 已加入（类型为 `GameEntry`，保证 `CreateModules()` 可用），
"配置入口"和"手动启动"都只是一行：

```csharp
[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]
static void Configure()
{
    Bootstrap.Options.Entry = new MyGameEntry();
    Bootstrap.Options.TestSceneContains = Array.Empty<string>();
}
```

### 1.3 P1 · 三套获取方式，调用方要记住"什么时候用哪个"

`Docs/01-架构总览.md:158-171` 自己列了三种：静态 `Instance`、MonoBehaviour 单例、`Modules.Get<T>()`。
实测（排除 `Plugins/3rd/GenerateScript/Editor/Tests`）：**198 处 `.Instance`，14 处 `Modules.Get/TryGet/Contains`**。
守卫把 `.Instance` 冻结在基线，但"冻结"不等于"迁移"。

**建议**（按代价从低到高）：

1. **先统一文档口径**：运行时只写 `Modules.Get<T>()`，`.Instance` 只出现在编辑器 / 测试；`Docs/00` 和 `Docs/05` 的表格保持这一条。
2. **给 `Modules` 加类型化快捷入口**（可选，纯糖）：
   ```csharp
   public static UISystem UI => Get<UISystem>();
   public static SoundSystem Sound => Get<SoundSystem>();
   ```
3. **接口化**（大改，放到 P2）：`IUIService` / `ISoundService` 放 `Base`，`Modules.Get<IUIService>()`。
   这样业务代码不依赖具体类，测试可替身，也顺便解决"模块没注册时拿到半初始化对象"的问题。

### 1.4 P1 · 模块清单手写，删模块靠运行期报错

`StartGame.CreateModules()` 手写 14 项（`Core/StartGame.cs:61-81`）。删掉一个模块时，依赖校验只**告警**并退回注册顺序（`ModuleCatalog` 的失败策略），启动不会中止 —— 对"最小接入"不友好：用户得先知道 14 个模块各自依赖谁。

**建议**：

```csharp
public static class ModulePresets
{
    public static IList<ICustomSystem> Full();      // 现在这 14 个
    public static IList<ICustomSystem> Minimal();   // Resources + Scene + UI
    public static IList<ICustomSystem> Without<T>(this IList<ICustomSystem> modules);
}
```

再加一个 `ModuleCatalog.ExpandDependencies(modules)`：把 `[ModuleOrder(_, typeof(X))]` 里声明的依赖自动补进列表（或在缺失时**直接失败**而不是告警）。这样"只留我需要的"从"背依赖表"变成"删一行"。

### 1.5 P2 · 命名空间与目录不一致

`Utils/` 的 rootNamespace 是 `ReunionMovement.Common.Util`（`Utils/ReunionMovement.Utils.asmdef:3`），
`Config` 又在根命名空间 `ReunionMovement`（`Common/Config/Config.cs:4`）。
接入方写一个窗口，通常要 `using` 5~8 个命名空间。这是 [重构方案](重构方案.md) 阶段 3 的既定内容，不展开。

### 1.6 P1 · 示例在框架里，不在 Samples 里

> 状态：✅ 已实现（2026-10-22）。新增 `Samples~/HelloWorld`（最小 `GameEntry` + asmdef + README，
> 不依赖场景/预制体，运行时创建 uGUI 文本）；UPM `package.json` 的 `samples` 字段已生成。

30 个场景里只有 5 个进了 Build Settings，`Scenes/Example/` 是"功能演示"而不是"按需导入的示例"。
新用户想抄一个最小工程，只能读 `Core/StartGame.cs` 自己拼。

**建议**：UPM 化时把 `Samples~/HelloWorld` 做成最小入口（示例不依赖场景，运行时创建 uGUI 文本）；
导入包后从 Package Manager 点 "Import Sample" 就能跑。这比再写一篇文档有效。

### 1.7 P3 · 文档只有中文

> 状态：✅ 已加英文 README + 平台矩阵（2026-10-22）。中文文档仍是主文档。

对外分发时，README 至少要有英文版 + 平台矩阵。不是阻塞项。

## 2. 跨平台

### 2.1 P0 · 没有构建流水线

> 状态：✅ 已实现（2026-10-22）。新增 `Editor/Build/ReunionMovementBuilder.cs`（菜单 + 命令行，6 个目标）。
> Windows 构建实测：**170.8 MB / 0 错误 / 1 分 21 秒**；Android 构建实测：**75 MB APK / 0 错误 / 10 分 16 秒**；
> WebGL / iOS 需在对应环境验证。

全仓库没有一处 `BuildPipeline.BuildPlayer`（`grep BuildPipeline` 只命中 Addressables 的 target 切换）。
CI 只构建 WebGL（`.github/workflows/unity-ci.yml:64`），Windows / Android / iOS 从未在 CI 里出过包。
"跨平台"目前是**代码里有分支**，不是**工程上可交付**。

**建议**：加 `Editor/Build/ReunionMovementBuilder.cs`：

```csharp
[MenuItem("ReunionMovement/构建/Windows")]
[MenuItem("ReunionMovement/构建/Android")]
[MenuItem("ReunionMovement/构建/WebGL")]
public static void Build(BuildTarget target) { /* 前置检查 + BuildPlayer */ }

// 命令行
// Unity -batchmode -quit -projectPath Unity/ReunionMovement \
//   -executeMethod ReunionMovement.EditorTools.Build.ReunionMovementBuilder.BuildFromCommandLine -buildTarget WebGL
```

前置检查至少包含：Addressables 是否安装、`activeInputHandler`、目标平台的 scripting backend、
Build Settings 场景清单、`link.xml` 是否存在、输出目录。

### 2.2 P0 · iOS 触觉是"断头路"

> 状态：✅ 已实现（2026-10-22）。新增 `Plugins/iOS/ReunionHaptics.mm`，9 个 `__Internal` 符号都有
> `UISelectionFeedbackGenerator` / `UIImpactFeedbackGenerator` / `UINotificationFeedbackGenerator` 实现。
> **iOS 链接仍需在 macOS/Xcode 上做一次最终验证**（当前环境是 Windows，无法跑 iOS 构建）。

`Utils/Util/VibrationUtil.cs:368-377` 在 `UNITY_IOS && !UNITY_EDITOR` 下声明了 9 个
`[DllImport("__Internal")]`（`InstantiateFeedbackGenerators`、`SelectionHaptic`…），
但仓库里**没有任何 `.mm/.m/.swift` 实现**（全仓库搜索为空）。

当前 `VibrationUtil` 没有调用点（只被 `HapticTypes` 枚举间接提及），所以问题是休眠的。
一旦业务代码调用 `VibrationUtil.Haptic(...)`，iOS 构建会在 Xcode 链接阶段报 undefined symbols，
或运行期 `EntryPointNotFoundException`。

**建议**：补一个 `Assets/Plugins/iOS/ReunionHaptics.mm`（`UIImpactFeedbackGenerator` 实现），
或者在 iOS 分支直接退回 `Handheld.Vibrate()` / 空实现，并在文档里明确"iOS 触觉不提供"。
不能保持"声明了但没人实现"的状态。

### 2.3 P0 · Android 振动缺 `VIBRATE` 权限

> 状态：✅ 已实现（2026-10-22）。新增 `Editor/Build/AndroidVibratePermission.cs`，在 Android 构建的
> Gradle 主清单里注入 `VIBRATE`；`VibrationUtil` 的 Android 调用全部包 `try/catch`，缺权限只告警一次，
> 不会再让静态初始化炸成 `TypeInitializationException`。Android release APK 构建通过，
> `unityLibrary/src/main/AndroidManifest.xml` 已确认包含 `android.permission.VIBRATE`；真机振动待验证。

`VibrationUtil.cs:184-220` 在 `#if UNITY_ANDROID` 下直接 `getSystemService("vibrator")` 并
`Call("vibrate")`；仓库里没有任何 `AndroidManifest.xml`，Unity 默认清单不含 `android.permission.VIBRATE`。
没有权限时 `vibrate` 会抛 `SecurityException`；而且这些字段是静态初始化，异常会变成 `TypeInitializationException`。

**建议**：加 `Assets/Plugins/Android/AndroidManifest.xml` 声明 `VIBRATE`（或写进接入文档的必做项），
并给 `AndroidVibrate` 包一层 `try/catch` + 一次性告警，避免整个类型初始化失败。

### 2.4 P1 · 没有 `link.xml` / 裁剪策略

> 状态：✅ 已实现（2026-10-22）。新增 `Assets/ReunionMovement/link.xml`，保留入口解析、生成配置、
> 生成 UI 与 `GameConfig`。Windows（Mono）与 Android IL2CPP release 构建均通过；
> High stripping 级别未单独调整，仍需真机运行验证。

仓库没有 `link.xml`。以下位置依赖反射或序列化，IL2CPP + High stripping 下有被裁掉的风险：

- `GameEntryResolver` 用 `Attribute.GetCustomAttribute` 扫程序集（`Core/GameEntryResolver.cs:67`）；
- `Config.EnsureLoaded()` 用 `Resources.Load<GameConfig>`（`Common/Config/Config.cs:39`）；
- `Newtonsoft.Json` 的泛型反序列化（`FileOperationUtil.DeserializeObject<T>`、`StateMachine`、`UnityHttpService` 三处运行时代码）；
- R3 / UniTask 的 AOT 路径。

**建议**：加一个最小 `link.xml`（保留 `ReunionMovement.*` 的入口类型、`GameConfig`、Newtonsoft 需要的模型），
并用 `Android` + `IL2CPP` + `Managed Stripping Level = High` 真机启动一次验证。
不要求现在就上 High，但要有这个文件作为"以后有人开 High 不会炸"的保险。

### 2.5 P1 · 新输入系统下还残留旧 Input API

`ProjectSettings.asset:950` 是 `activeInputHandler: 1`（仅新输入系统），
但 `Utils/ScreenResolution/AspectUtility.cs:166,167,182` 仍调用 `UnityEngine.Input.mousePosition`。
该文件当前**没有调用点**，所以是休眠状态；一旦被使用，会在所有平台抛
`InvalidOperationException: You are trying to read Input using the UnityEngine.Input class, but you have switched active Input handling to Input System package`。

**建议**：改成 `Mouse.current?.position.ReadValue()`，或直接删掉这个没人用的工具类。

### 2.6 P1 · 兼容级别是 .NET Framework，不是 .NET Standard

`ProjectSettings.asset:948` 是 `apiCompatibilityLevel: 3`（.NET Framework 4.x）。
Unity 6 的默认推荐是 .NET Standard 2.1；跨平台（WebGL/iOS）用 Standard 更稳，
也更容易发现"用了某个平台没有的 API"。

**建议**：切到 .NET Standard 2.1，然后跑一次全平台编译。会暴露少量 API 差异，但这是好事。

### 2.7 P1 · WebGL 的文件落盘要真机验证

`SaveSystem` 用 `System.IO` 写 `persistentDataPath/Data`（`Utils/Util/SaveSystem.cs:23`），
`FileOperationUtil` 也走 `System.IO`。WebGL 下 `persistentDataPath` 是 Emscripten 的 MEMFS → IDBFS，
仓库里没有显式的 `FS.syncfs` 调用（`HTTPHelper.cs:336` 的注释已经提到这层映射）。

**这不是已确认的 bug，而是必须验证的项**：WebGL 构建 → 存档 → 刷新页面 → 读档。
如果丢档，就加一个 jslib 的 `FS.syncfs`，在 `OnApplicationPause/OnApplicationQuit` 或定时调用。

### 2.8 P1 · CI 只覆盖 WebGL

> 状态：✅ 已补齐 job（2026-10-25）。新增 `license-check`：没有 `UNITY_LICENSE` 时，Unity 测试/构建 job 安全跳过并给 warning；配置 secret 后自动运行 EditMode、WebGL、Windows、Android。

`unity-ci.yml` 现在包含：`editmode-tests`、`webgl-build`、`windows-build`、手动 `android-build`、`guard-only`。
当前公开运行因仓库尚未配置 `UNITY_LICENSE`，Unity job 会跳过；`guard-only` 独立运行。

**接入仓库时**：在 GitHub Secrets 添加 GameCI 的 `UNITY_LICENSE`，再手动触发一次 workflow 验证 Android/Windows/WebGL。

### 2.9 P1 · 129 MB 字体跟着框架走

`Assets/ReunionMovement` 共 192.6 MB，其中 `Fonts/` 129.2 MB（7 套中文字体 + 预烘焙 SDF 图集，
单张 SDF 最大 32.6 MB）。这些字体和框架逻辑无关，但会进入包、拖慢首次导入、撑大 `.unitypackage`（75 MB）。

**建议**：默认只留 1 套（例如 HarmonyOS Sans），其余移到 `Samples~/Fonts` 或独立包；
SDF 图集改成 Dynamic + 按需生成，或走 Addressables 远程。

### 2.10 P2 · "低版本兼容"的声明过宽

> 状态：✅ 已修正（2026-10-22）。README 改为平台支持矩阵，最低版本写明 `6000.3`；2022.3 及以下未验证。

`README.md` 写"低于 2022.3 的版本……更低版本（如 2019）可能需要手动解决少量语法差异"。
但代码用了 `FindObjectsByType`（2022.2+，`Core/Bootstrap.cs:280` 等 14 处）、
URP 17.3 / Unity 6 包，2019 基本不可能直接跑。

**建议**：把最低版本改成实际验证过的 `6000.3`（或 `2022.3 + 降级 URP`），并在 README 放一张平台矩阵。

## 3. 插件便携性

### 3.1 P0 · 没有可版本化的分发包

> 状态：🟡 已实现导出器与运行时包（2026-10-22）。`ReunionUpmExporter` 可生成标准 UPM 包；
> 新建 Unity 6000.3 工程用 `file:` 安装后 0 编译错误、依赖自动解析。发布到公开仓库/Release 的方式待定。
> 操作见 [UPM 打包指南](Packaging/UPM打包指南.md)。

改造前只有两种分发方式：

| 方式 | 现状 | 问题 |
|---|---|---|
| `.unitypackage` | `Editor/Package/ReunionMovementPackageExporter.cs` 一键导出全量 `Assets/ReunionMovement` | 75 MB、导入后 188 MB、无版本、无依赖解析、升级只能整包覆盖 |
| 拷贝目录 | 手动复制 `Assets/ReunionMovement` | 同上，且容易漏 `.meta` |

没有 `package.json`、没有 `CHANGELOG`、没有 git tag 驱动的安装方式。
`Docs/重构方案.md:519` 说"阶段 0–3 完成前不要把框架塞进 UPM 包" —— 这个判断在当时是对的（包内改文件会触发重导入），
但**"源码继续放在 `Assets/` 迭代"和"对外提供 UPM 包"并不冲突**：用导出器从 `Assets/` 生成包即可。

**建议**：加 `Editor/Package/ReunionUpmExporter.cs`，产出：

```text
Build/Packages/com.reunion.movement/
├── package.json          # name/version/unity/dependencies/samples
├── README.md
├── CHANGELOG.md
├── LICENSE.md            # Apache-2.0
├── Common/ Core/ Utils/ Plugins/ Resources/ Scenes/
├── Editor/
├── Documentation~/
└── Samples~/HelloWorld/
```

`package.json` 至少声明：

```json
{
  "name": "com.reunion.movement",
  "displayName": "Reunion Movement",
  "version": "1.1.0",
  "unity": "6000.3",
  "license": "Apache-2.0",
  "dependencies": {
    "com.unity.addressables": "2.9.1",
    "com.unity.inputsystem": "1.18.0",
    "com.unity.ugui": "2.0.0",
    "com.unity.render-pipelines.universal": "17.3.0"
  }
}
```

安装方只需要：

```json
"com.reunion.movement": "https://github.com/<you>/Reunion-Movement.git?path=/Build/Packages/com.reunion.movement#v1.1.0"
```

> 注意：`Build/` 默认被 `.gitignore` 忽略。要支持 git URL 安装，包必须提交到仓库里
>（例如 `Distribution/com.reunion.movement`），或者发一个独立的包仓库。

### 3.2 P0 · 第三方程序集与官方包重名

> 状态：✅ P0 已收口（2026-10-22）。检测器 + Newtonsoft 官方包 + SharpZipLib 删除；
> 新增 OpenUPM 模式（仅 UniTask，空工程验证通过）；R3 / ZString / DOTween 仍内置（官方包结构限制）。
> 详见 [第三方依赖](第三方依赖.md)。

这是"接入方已经装了 UniTask"时最可能炸的一条。当前 vendored 的第三方：

| 组件 | 版本 | 程序集名 | 与谁冲突 | 后果 |
|---|---|---|---|---|
| UniTask | 2.5.11 | `UniTask` | `com.cysharp.unitask`（同名 asmdef） | Unity 报"同名程序集"，直接不编译 |
| R3 | 1.3.1 | `R3` | `com.cysharp.r3` | 同名 DLL，重复类型 `CS0433` |
| ZString | 2.6.0 | `ZString` | `com.cysharp.zstring` | 同上 |
| DOTween | — | `DOTween` | DOTween 官方包 | 同上 |
| Newtonsoft.Json | 3.2.2（官方包） | `Newtonsoft.Json` | 已切官方包，不再内置 | — |
| SharpZipLib | — | — | 已删除（框架 0 引用） | — |

`UniTask` 尤其致命：它几乎是 Unity 项目的默认依赖，接入方"先装了 UniTask 再装框架"是常态。

**建议**（按彻底程度）：

1. **能走 UPM 的走 UPM**：UniTask / R3 / ZString 都有官方包，声明成 `dependencies` 即可，框架代码不用改。
   DOTween 走 Asset Store / OpenUPM，文档写清楚。
2. **必须 vendored 的改名**：把 `UniTask.asmdef` 的 `name` 改成 `ReunionMovement.UniTask`，
   同步改所有引用它的 asmdef；这样即使宿主装了官方 UniTask，也只是多一个程序集，不会同名。
   DLL 类（R3/ZString/DOTween）改不了程序集名，只能走第 1 条或"不要同时装官方包"的文档约定。
3. **删掉没用到的**：`ICSharpCode.SharpZipLib.dll` 在框架里 0 处引用，直接删。**已删除。**

> 已落地：`ThirdPartyDependencyChecker`（菜单 + 批处理）+ [第三方依赖](第三方依赖.md)；
> Newtonsoft 改用 `com.unity.nuget.newtonsoft-json` 3.2.2，SharpZipLib 已删。

### 3.3 P0 · 编辑器工具写死 `Assets/ReunionMovement`

> 状态：✅ 已实现（2026-10-22）。新增 `ReunionMovement.Editor.Shared` 程序集与 `ReunionPaths`；
> 24 处硬编码已全部替换，读写分离（`InFramework` / `InWritable`），包安装时生成物落到 `Assets/ReunionMovementGenerated`。

8 个文件、24 处硬编码（`AddressablesMigrator` 10 处、`ExcelSystem` 4 处、
`ArchitectureGuard` 3 处、`CreateUIPlane` 3 处，其余各 1 处）。
一旦框架以 UPM 安装到 `Packages/com.reunion.movement/`，这些工具会：

- 读错目录（找不到资源、守卫扫描空目录）；
- 往只读的包目录里写（UPM 包不可写，`AssetDatabase.CreateFolder` 会失败）；
- 在宿主工程的 `Assets/ReunionMovement/...` 下创建一堆空目录，污染工程。

**建议**：加一个 `ReunionPaths`（Editor 程序集），用 asmdef 定位框架根：

```csharp
internal static class ReunionPaths
{
    public static string Root { get; } = Locate();
    public static string InFramework(string rel) => Root + "/" + rel;

    // 生成物必须写到用户工程，不能写进包
    public static string GeneratedRoot => "Assets/ReunionMovementGenerated";

    private static string Locate()
    {
        foreach (var guid in AssetDatabase.FindAssets("ReunionMovement.Core t:AssemblyDefinitionAsset"))
        {
            var path = AssetDatabase.GUIDToAssetPath(guid);
            const string suffix = "/Core/ReunionMovement.Core.asmdef";
            if (path.EndsWith(suffix, StringComparison.Ordinal))
                return path.Substring(0, path.Length - suffix.Length);
        }
        return "Assets/ReunionMovement";
    }
}
```

然后把 24 处常量换成 `ReunionPaths`；**读**用 `Root`，**写**（导表产物、生成的 UI 脚本 / Prefab / 场景）用 `GeneratedRoot`。
这一步是 UPM 化的前置条件，也是"插件便携性"最实的一块。

### 3.4 P1 · `Resources` 路径没有命名空间

`Config` 里是 `Resources.Load("ScriptableObjects/GameConfig")`、`"Prefabs/UIs/"`、`"AutoDatabase/"`
（`Common/Config/Config.cs:19-22,39`）。这些都是 `Resources` 根下的通用名字，
宿主工程只要有同名路径，`Resources.Load` 就会拿到不可预期的那个（重复时行为未定义）。

**建议**：迁到 `Resources/ReunionMovement/...`（移动资源时连 `.meta` 一起，GUID 不会变），
同步改 `Config` 常量；或者干脆全部走 Addressables。

### 3.5 P2 · `.unitypackage` 无清单、无排除

`ReunionMovementPackageExporter` 只做了一次 `ExportPackage(ExportRoot, Recurse)`，
没有排除示例、测试、字体、Docs，也没有"最小包 / 完整包"的选项。
接入方拿到的是 188 MB 的"整个仓库快照"，不是"框架"。

**建议**：导出器接受 `PackageProfile`（`Minimal` / `Full` / `Custom`），
至少把 `Scenes/Example`、`Tests`、`Docs`、`Fonts`（可选）排除；同时在导出日志里打印清单与体积。

### 3.6 P2 · `3rd/WebGLSupport` 自带 `package.json`

`3rd/WebGLSupport/package.json` 写的是 `com.github.kou-yeung` v1.4.2，但它在 `Assets/` 下，
Unity 不会把它当包；这个文件只会让人误以为可以单独升级。建议移到 `Documentation~` 或加注释说明来源。
