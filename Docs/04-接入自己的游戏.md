# 04 · 接入你自己的游戏

框架和你自己的游戏之间只隔着一个类：**`GameEntry`**。

## 现状：仓库里还没有 `Game/` 层

必须先说清楚这件事，否则会白找半天：

| 你以为有的 | 实际的 |
|---|---|
| `Game/Entry/MyGameEntry.cs` | **不存在**。仓库自带的入口是 `Core/StartGame.cs`（`StartGame : GameEntry`） |
| 一个独立的业务程序集 | 入口声明就在 `Core` 程序集里：`[assembly: ReunionGameEntry(typeof(StartGame))]` |
| 示例与框架已经分开 | 示例场景、示例 UI 都还在同一个工程里 |

也就是说，**当前工程 = 框架 + 一个叫 `StartGame` 的参考实现**。
接入自己的游戏有两种做法，选一种即可。

## 做法 A：改 `StartGame`（最快，适合先跑起来）

1. `Core/StartGame.cs` 里的 `CreateModules()` 删掉不需要的模块；
2. `OnGameStartAsync()` 里换成你自己的开局逻辑；
3. 启动场景与首个窗口用常量控制（`StartGame.cs` 顶部）。

```csharp
// 删掉不用的模块，ModuleCatalog 会检查依赖是否仍然满足
modules.RemoveAll(m => m is TerminalSystem);
```

删模块时注意依赖：`SoundSystem` 依赖 `ResourcesSystem` 和 `AddressableSystem`，
把后者删掉启动会直接失败并打印缺哪个依赖。

## 做法 B：独立的入口程序集（推荐，干净）

### 1. 建你自己的程序集

在 `Assets/` 下任意位置（**不要**放进 `Assets/ReunionMovement/Core/`）新建 asmdef，例如 `MyGame.asmdef`，
引用你需要的框架程序集：

```
ReunionMovement.Core
ReunionMovement.Base
ReunionMovement.Common
ReunionMovement.Utils
UniTask
```

### 2. 写入口类

```csharp
using System.Collections.Generic;
using Cysharp.Threading.Tasks;
using ReunionMovement.Core;
using ReunionMovement.Core.Base;

namespace MyGame
{
    public class MyGameEntry : GameEntry
    {
        public override IList<ICustomSystem> CreateModules()
        {
            return new List<ICustomSystem>
            {
                ResourcesSystem.Instance,     // 10
                AddressableSystem.Instance,   // 20
                UISystem.Instance,            // 90
                // 只留你需要的
            };
        }

        public override UniTask OnBeforeInitAsync()
        {
            // 加载你自己的配置
            return UniTask.CompletedTask;
        }

        public override UniTask OnGameStartAsync()
        {
            // 所有模块 Init 完成 → 这里进入你的游戏
            return UniTask.CompletedTask;
        }
    }
}
```

`GameEntry` 只有三个可重写点：`CreateModules()`（虚方法）、`OnBeforeInitAsync()`、`OnGameStartAsync()`（抽象）。

### 3. 声明你的入口

```csharp
// 放在你自己程序集的任意 .cs 文件顶部（命名空间外）
[assembly: ReunionGameEntry(typeof(MyGame.MyGameEntry))]
```

`GameEntryResolver` 的挑选规则是：**优先采用非框架程序集的声明**，
所以你不必删掉 Core 里那条 `[assembly: ReunionGameEntry(typeof(StartGame))]`，它会被自动让位。

也可以在代码里显式指定，跳过所有解析逻辑：

```csharp
Bootstrap.Disable();                                   // 关掉自动启动
await Bootstrap.StartAsync(new MyGameEntry());         // 自己决定用哪个入口
```

注意 `BootstrapOptions` 里**没有**入口字段——入口只走两种方式：
`[assembly: ReunionGameEntry]` 声明，或直接传给 `Bootstrap.StartAsync(entry, modules)`。

## 改启动场景与首个窗口

```csharp
// Core/StartGame.cs 顶部（做法 A）；做法 B 里改成你自己的常量
public const string BootSceneName = "MyBootScene";
public const string StartupWindowName = "MainMenuUIPlane";
```

`BootSceneName` 决定初始化完成后进哪个场景；`StartupWindowName` 决定进场景后自动打开哪个窗口。

## 关掉示例

示例场景的判断在 `BootstrapOptions` 里，两条规则是**或**关系：

```csharp
public string[] TestScenePrefixes = { "Test", "_" };
public string[] TestSceneContains = { "Example", "UIPlaneScene", "Music", "Audio", "Debug" };
```

命中任意一条，就直接跳到 `Temp.unity`（一个空场景），不加载业务场景。
接入自己的游戏后建议改为：

```csharp
Bootstrap.Options.TestScenePrefixes = new[] { "Test" };
Bootstrap.Options.TestSceneContains = new string[0];
```

> 设置时机必须在 `Bootstrap` 初始化之前——用 `[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.AfterAssembliesLoaded)]` 的钩子，别放在 `Awake` 里。

## 隔离示例资源（可选，但建议）

示例场景、`UI/Select`、`Utils/**/Example` 目前和框架在同一个工程、同一批程序集里。
彻底隔离需要把它们移到 `Assets/Samples/` 并配独立 asmdef——这一步必须在 Unity 编辑器里做
（移动 `.cs` 必须连 `.meta` 一起移，否则预制体引用会断）。

## 验收

| # | 检查 | 期望 |
|---|---|---|
| 1 | Play 启动场景 | 日志里出现 `模块顺序: …` 且只有你保留的模块 |
| 2 | 控制台 | 没有 `ModuleCatalog` 的依赖告警 |
| 3 | 进游戏 | 直接进你的 `BootSceneName`，不是 `Temp` |
| 4 | 首个窗口 | `StartupWindowName` 对应的窗口自动打开 |
| 5 | 守卫 | `ReunionMovement → 守卫 → 运行架构检查` 全绿 |
